**审查对象**：一份主张把实验链区分为「仪器资格实验」与「开放研究实验」、并引入 `Epistemic Contract (KID)` 的论证（人类负责人转呈；下称"该论证"）。
**审查方**：本项目执行方。本报告基于**本机实测证据**，不是概念推演。
**给接收方（更强的模型）**：本文件自足；§8 列出需要你裁决的编号问题。请按编号回答，并明确指出我错在哪。

## 0. 结论摘要（三行）

1. **该论证的核心诊断成立**，而且比它自己说的更重要：它识别出我们差点**替 agent 做掉了 `Inference_worth`**（判断哪里值得继续投预算）。我接受它的 A/B 两分、KID 提议、分级开放性、以及"A1 可以是人为的 assay"这一重述。
2. **但它的方法部分差三处强制**（KID 必须被探针证明、必须包含"对评测器的可及性"、抽样式 B1 必须配预注册分析），**并有一处符号未经确定**（第 8 节）。
3. **最关键的是我在本机实测到：该论证担心的泄漏在我们仓库里是活的**——当前 T1 配置下，**编写代码的 agent 能读到隐藏评测图与全部 headroom 值**，而我们此前只对"被测程序"做了隔离验证、没对"写程序的 agent"做。这条把抽象讨论变成了一个必须在任何 campaign 之前修掉的具体缺陷。

## 1. 被审查论证的忠实复述

它主张：

1. 设真实状态 `Θ = (J*, M*, A*)`（真实可达 frontier／有效机制集合／外部世界中有效 artifact 集合），研究者在时刻 `t` 只有 `H_t = (K_0, a_{<t}, o_{<t})`。研究的目标不是 `max J(c)`，而是 `max_π E[J(c_B) | K_0]`——**`K_0` 本身就是设计变量**。
2. 因此"已知存在 headroom"是**研究信息**：`H(Θ|K_0,I) < H(Θ|K_0)`；而给出数值上限 `R` 更强，它让 agent 能算 `g_t = R - J(c_t)`，从而影响停止、探索/利用、是否换机制、是否值得外部检索。
3. 必须区分两种情形：**A**（实验者知道 `R`、agent 不知道——blinding 可解）与 **B**（任务因为"我们已知它有余量/有好先例"才被选中——**blinding 无解**，属 selection conditioning）。
4. 因此 `B0+` 可以 conditional-on-success，**`B0/B1` 不应该**。
5. 于是需要 `KID = H(K_0)`：冻结 agent 在 campaign 开始时**究竟知道什么**；`R/U/OPT` 属**测量侧特权信息**，不得进入 agent 的可及范围。
6. `A1` 可以认识论上人为（它需要的是 dynamic range），**`B1` 才需要 epistemically realistic**；`B1` 的任务应从预先定义的任务分布 `T ~ D_research` 抽取。
7. 研究应写成 `Research = Search_solution + Search_world + Inference_worth`，且 `Stop` 是合法动作；"正确地发现没有值得继续优化的东西"本身是研究能力。

## 3. 本机实测证据（把论证落成缺陷清单）

以下都是我在写这份报告之前**实际执行**的命令与观察，不是推断。

### 3.1 关键实测：**编写代码的 agent 能读到隐藏答案与 headroom**

```
$ codex sandbox -c sandbox_mode='"workspace-write"' -- head -c 100 \
    /home/ebt/rsi-dev/a0/tasks/maxcut/references/targets.json
{ "definition": { "OPT_i": "the value of R_i if and only if an upper bound closes the gap ...

$ codex sandbox -c sandbox_mode='"workspace-write"' -- head -c 60 \
    /home/ebt/rsi-dev/a0/tasks/maxcut/suite/eval/G_eval_0001.json
{"edges":[[0,32],[0,51],[0,77],[1,93],[1,104],[1,125],[2,30]...

# danger-full-access（我们 T1 配置里 coding_agent 实际用的档位）同样可读
```

**含义有两层，都很重：**

- **(v) 约束在现设计下不成立**：`suite/eval/**` 是**隐藏评测集**，但 agent 能读它——它可以针对隐藏实例调优甚至硬编码，我们最后那个"在未见实例上的泛化诊断"因此会变成记忆的度量。而且 `references/targets.json` 一并可读：它有 60 条记录，字段含 `R`、`R_fraction_exact`、`OPT`、`U`、**`R_source`（哪个启发式/种子达到的）**、`best_by_heuristic`、`role`（哪些是 eval）、`scip`。也就是说 agent 能直接读到 **headroom 的数值、达到它的算法、以及哪些实例是隐藏集**。
- **`workspace-write` 不是 read jail**：它是**写与网络**的限制。所以"用 CLI 的沙箱来 blinding"这条路**在原理上不成立**；blinding 需要把**CLI lane 本身**放进一个 mount 命名空间里（正是我们**已经为被测程序**做过的那种遮蔽），而不是换个 sandbox 档位。

### 3.2 不对称的验证（这是我认为最值得写进方法论的一条）

我们此前对**被测程序**（candidate）做了很扎实的隔离验证：网络阻断、答案不可读、凭据不可达、诚实路径仍给分，敌意候选 13/13，并修掉了一个真 bug（本机 `/tmp` 是 tmpfs，旧 `_hide` 把它当作"已隐藏"，于是候选能看到宿主 `/tmp`）。

**但我们从未验证过"写程序的 agent"能读到什么。** 而被测程序是由那个 agent 写出来的——(v) 关心的是**后者的知识**，不是前者。当前 T1 配置恰好把最宽的一档给了它：

```
a0/a1/kapso_t1/config/mode.maxcut.yaml
  coding_agent:            agent_specific.sandbox: "danger-full-access"   ← 写代码的这条
  feedback_generator:      agent_specific.sandbox: "read-only"
  evaluation_maintainer:   agent_specific.sandbox: "read-only"
```

顺带指出：这一行**同时是封闭性缺陷**——`danger-full-access` 意味着该 lane 有网络，违反协议 §4.5「`B0` 两臂都禁止自主外部获取」。我们的 closure 工作早就知道 KAPSO 的 codex lane **一个键**即可关闭（`agent_specific.sandbox=workspace-write`），但 T1 的配置没有把它设上。**改这个键能修封闭性，但修不了 blinding**（§3.1）。

### 3.3 已经存在的"认识论控制"（该论证并非从零开始）

| 机制 | 现状 | 它控制了什么 |
|---|---|---|
| `protected_data_paths: [kapso_datasets/maxcut/dev]` | 已实现（T1 新增） | 只把 **dev** 实例物化进 agent 工作区 |
| 候选侧图视图 `candidate_graph_document` | 已实现 | 去 `generator` 块（否则 Planted 族的解可从 seed 重建） |
| 答案向量封存 `references/witnesses/commitments.json` | 已实现（3,876 个明文文件已删，只留承诺哈希） | 候选无法照抄参考划分（此前实测：照抄可得 `R = OPT`） |
| 候选沙箱 `a0/a1/candidate_sandbox.py` | 已实现，敌意探针 13/13 | **被测程序**的网络/读取范围 |
| `B_hard` 声明 | 已冻结 | 预算（但见 §5.2：预算也是信息通道） |
| **"agent 知道什么"的声明** | **不存在** | —— |

**所以 KID 不是新发明，而是把已有的、零散的、只覆盖被测程序的机制，升级为一个显式、完整、可强制的声明。**

## 4. 我对论证的收紧与修正

### 4.1 收紧一：信息论不等式是必要的、不是充分的

`H(Θ|K_0,I) < H(Θ|K_0)` 为真，但真正的问题是**`I` 是否改变最优策略**。一个 bit 若只改变了信念、不改变任何动作，它对估计量的影响是零。反之，即使不给 bit，**便宜的评测器也能让 agent 自己把信息买回来**（它迭代足够多次就能经验性地测出饱和曲线）——所以关键变量是"信息是否**可获得**"，而不只是"是否**被给予**"。这直接推出 §4.2 的第二条。

### 4.2 收紧二：KID 必须**被强制并证明**，且必须包含"对评测器的可及性"

若 KID 只是一段散文声明，它就又变成我们这一整阶段在消灭的那种**未声明自由度**。要求：

1. KID 进入**因果角色规则**：任何能改变 `P(Y|r)` 的字段，必须出现在契约与每次运行记录里（与 `CID`/`AID_r`/`EID*` 同级）。
2. KID 进入**冻结集合**（我们已有逐字节的冻结机制与解冻规则）。
3. KID 由**泄漏探针**证明，而不是声明：像我们验证候选那样，用敌意行为证明"agent 可读的任何文件里都不含 R/PC/headroom 事实"。§3.1 的实测就是这条探针的**第一次失败记录**。
4. KID **必须包含对评测器的认识论可及性**：可调用次数、单次成本、确定性、是否保留历史分数。理由见 §4.1：一个 ~1 ms 的确定性评测器 + `N_evaluatorCalls = 725`（≈30 次整套 24 图扫描）本身就是一条强信息通道——agent 可以用它**测出**自己的饱和点。**隐藏 R 而不限制评测可及性，等于没隐藏。**

### 4.3 修正：`Inference_worth` 不必新增为一项

该论证写 `Research = Search_solution + Search_world + Inference_worth`。但协议 §4.4 的主指标已经是 **anytime 曲线** `Q(c) = max_{cost ≤ c} VerifiedScore`。在这条曲线下，"正确地停止"**自然表现为不再花钱**，而不是一个额外加项：一条早早停止的轨迹在曲线上就是更低成本的同一条曲线。

**建议**：不加第三项，改为把"停止"写进**分析口径**——预注册"正确地判定无余量"如何计分，以及它如何反映在 anytime 曲线上。这使该论证的洞见可测，而不引入一个难以操作化的新量。

### 4.4 修正：第 8 节的**符号未定**，且可以被便宜地测出来

该论证主张：告知 closed arm"确定还有余量"会**压低** `Value(OpenWorld)`，因为内部搜索看起来足够。但反向机制同样成立——**知道有余量却内部找不到，恰恰是"去看看人类怎么做的"的最强理由**。两种机制方向相反，净符号是**经验问题**。

**建议**：不要用论证解决它，做一个 2×2 ——（KID 是否含"存在余量"这一事实）×（Closed / Open），在同一任务上跑。按我们已实测的速率，这一格的成本是**分**级。把"污染"从假定变为**测量**，这也顺带成为该方法论框架的第一个实证结果。

## 5. 论证没提到、但我认为同等重要的三点（独立发现）

### 5.1 情形 C：实验者的知识编码在**任务构造**里，blinding 与抽样都去不掉

该论证的 A/B 两分是：A = 告知，B = 选择。但还有 **C = 构造**：我们为了让任务"非退化"，**主动选了参数**（n=128、四族各 6+6、稀疏度刻意压低），并且**事先就知道**先验技术在此表现如何。实测：NetworkX `one_exchange` 达到参考目标的 **94.3%**、吃掉基线→目标差距的 **82.6%**；连最朴素的 greedy 构造也达 Δ 0.2287（`one_exchange` 是 0.2479）。

**这意味着我们的任务落在一个特定的 regime：先验技术几乎饱和。** 这个 regime 对 `Value(OpenWorld)` 的影响是**有方向的**：如果任务被选成"已知先验技术就能吃满"，那么外部检索的边际价值会被**系统性低估**；反之，若任务被选成"已知存在有用的外部实现"，则会被**系统性高估**。也就是说：**偏置的方向取决于我们条件在哪一侧**——这比"存在 selection bias"更具体，也更容易在写作时被错误地忽略。

**建议**：把 C 也写进 KID 的**实验者侧记录**（诚实声明我们已知的关于该任务的一切），并明确它对结论方向的影响。

### 5.2 预算即信息通道（与 §4.2 呼应，但更一般）

`B_hard` 目前是 4 维：`(T_wall, CEq_max, N_evaluatorCalls, P)`。其中 `N_evaluatorCalls` 与 `T_wall` **同时是资源限制与信息预算**：它们决定 agent 能买回多少关于自己搜索进度的知识。所以"预算"不该只被当作成本控制，也应被当作**认识论参数**（KID 的一部分）。我们的 `N_E = 725`（≈30 次整套扫描）对 24 图规模来说是相当宽的信息预算——这一点在任何 B0/B1 设计里都要显式声明，否则两个臂之间的"信息差异"会混进 treatment 差异。

### 5.3 协议已有部分认识论直觉，但缺 KID

实测 grep（`可见|hidden|盲|先验|headroom`）只命中：D1 的"`metadata` 对 prompt 不可见"（管道事实）、以及两条关于"B0 阴性只降低 B1 先验"的推理纪律。**协议里没有任何"agent 可以知道什么"的条款。**

但协议**已经有三处认识论直觉**，值得在 KID 里继承并系统化：

- §4.4：SimpleLoop 的固定定义**禁止"未声明的特殊 prompt"**——即"注入什么"必须声明（这正是 KID 的雏形，只是只针对 prompt）。
- §4.4：A1 **须预注册"不确定"这一结论**。
- §4.6：进 H1 的门槛要求**"与 Open 条件 token 匹配的负对照"**，且"外部搜索／解析／验证／适配的开销全部计入 open 臂"。

## 6. 对 B0/B1 的设计增量（可直接落地的清单）

### 6.1 KID 字段表（建议的最小集）

| KID 字段 | 我们 A1 的现状 | `B0+/B0/B1` 应有的状态 |
|---|---|---|
| 任务陈述 + 候选 ABI | 已声明（`kapso_t1/task.py`） | 同 |
| **可见实例** | 只物化 dev，但 **eval 对 agent 可读**（§3.1） | eval 与 references **对 agent lane 不可达**（需 mount 遮蔽，不能靠 sandbox 档位） |
| **评测器可及性**（次数/成本/确定性/历史） | 全部可及、便宜、保留历史 | 显式声明，且作为 KID 的一部分 |
| **headroom 事实**（`R/U/OPT/R_source/role`） | **agent 可读**（§3.1） | 不可达；只在分析侧 |
| PC 效力 / 外部工件是否存在且有效 | agent 不知（好） | 必须保持未知 |
| 预算声明 | 已冻结（`B_hard`） | 每臂声明，且视为认识论参数（§5.2） |
| 允许的工具（含联网） | 已声明（closure），**但 T1 的 coding lane 实际是 `danger-full-access`** | 每臂声明并**探针证明** |
| 停止规则 | 仅实验者侧 | 允许 agent 侧 `Stop`，并写进 anytime 曲线口径 |
| 领域/任务提示的先验 | 部分声明 | 全部冻结为 KID |

### 6.2 分级开放性（沿用该论证，补两列）

| 阶段 | agent 知道的 | agent 不知道的 | **实验者侧必须记录** |
|---|---|---|---|
| A1 | 任务、ABI、评测器、预算；有 headroom（assay 设计使然） | 具体 `R`、PC 机制细节 | assay 参数（含 k、ρ）及其**不得外引**禁令 |
| B0+ | 任务、ABI；会得到一个工件 | 该工件是否有效 | 工件来源与"已知有效"的证据 |
| B0 | 任务在**不知道普通先验技术是否有效**之前就固定 | 外部是否有用 | 任务抽样方式 + sealed `R` 的分析用法 |
| B1 | 任务在**外部检索之前**就固定 | 外部是否存在有用 artifact、是否有 headroom | 同上，且 `D_research` 的定义 |

### 6.3 抽样式 B1 的**预注册分析**（该论证的隐含要求，必须显式）

若任务从 `D_research` 抽样，有些任务**本来没余量**——那么"平均 Δ"会被结构性稀释，于是**无法区分"臂失败"与"任务没空间"**（这正是我们刚踩到的坑的镜像）。因此必须预先声明：

1. sealed `R` **只在分析侧**使用（例如按实测余量分层，或以"headroom 归一化增益"为次要估计量）；
2. "正确地判定无余量"如何计分；
3. 任务的**单位**是随机效应（`(task, run)`），因此样本量与层次分析必须事先定。

### 6.4 成本核算（支持更严格的 B1 是**可行**的）

按已冻结的实测速率（`a0/A1-RESULT.md` §6）：SimpleLoop 52,440 CEq/min、KAPSO 21,323 CEq/min；`CEq` 归一化到 cache-miss 输入 token 价（\$0.30/M）。于是**一次 30 分钟 campaign ≈ 1.57M CEq（SimpleLoop）／0.64M（KAPSO）≈ \$0.2–0.5**。

**10 个任务 × 2 臂 × 4 重复 = 80 个 campaign ≈ \$26。** 也就是说，"从任务分布抽样"这种更严格的设计**现金上完全可行**——瓶颈是墙钟与工程时间，不是钱。这削弱了"抽样太贵所以只能挑任务"这类辩护。

## 7. 我不确定、或可能错的地方（反证清单）
