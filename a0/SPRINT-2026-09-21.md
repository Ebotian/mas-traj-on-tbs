## 2. 关键结果

### 2.1 `Q_r` 与 `Eligible(r)`

`Q_r = (A0.1_measured, A0.1_adapted, A0.2_mechanism, A0.2_E2E, Closure)`，四个 runtime 各一行，每个分量带证据路径。谓词有两个阈值向量：`T_strict`（要求 A0.1 measured 满 14）与 `T_literal`（只要求 ≥1）。验证者从**原始证据**手工重算了两套分量，与声明一致；closure 分量与 `a0/closure/closure.<r>.json` 的 `verdict`/`study_verdict` 逐字段对得上，不是摘要。

**验证者的证伪**：`T_literal` 会放行 Eve 与 Loreley，而 `QUALIFICATION.md` 自己的 unproven 表把它们的 E2E 轮次记为 **UNPROVEN**、closure 记为 **NOT RECONCILED**。也就是说宽松向量会把"E2E 未证"的 runtime 判为可入 A1——正是审查第 8 条担心的稀释，只不过这次发生在谓词内部而不是报告措辞里。**这是决策项 D2。**

### 2.2 EvE 标签修正，以及它暴露的第二个问题

`report.json` 顶层现在给出 `eve = "PARTIAL (5/14 measured)"`、`n_pass=3 n_partial=1`，且 `r_1_a0_1_only` 不含 eve；`selftest.py` 20 个 fixture 行为不变；下游 `qualification` 在两个脚本上仍然通过。同时修掉了验证者发现的余留：`adapter_declared_verdict` 一类别名（适配器自述，却被放在 verdict 形状的键位上）改名成 `adapter_claim__untrusted` / `adapter_self_declaration__untrusted.claim__untrusted`，机器可读层面**不再存在**可被误读为 EvE 裸 `PASS` 的键（有一行式自检命令写进了 `a0/conformance/README.md`，验证者独立重跑确认）。

这次改名把变异 fixture 引用的 `conformance.py` pin 从 `45cc4e90…` 推到 `f33659f6…`，按那份 fixture 自己的规则必须重跑——已重跑，**七行逐字段一致**（含每行 14 个候选的数值、delta、findings）。改名前后的对照与比对工具都在其目录里。

### 2.3 执行证明书：两个方向都被证实，一个缺陷仍然活着

- **正向**：真实 `E*` 的证明书 `Q1 RECOMPUTES / Q2 SEMANTIC_MATCH / Q3 REALIZED`（exit 0）；被篡改的评测器（`sum_radii += 1e-3`）被 **Q3 NOT_REALIZED** 拒绝（exit 3）。
- **TOCTOU 时窗是真实的假绿来源**：先哈希路径、再执行路径，在"哈希后 ~6 秒、执行前 ~4 秒"把评测器换成 `+1e-3` 的版本，证明书仍打印干净身份，而数字已偏移；**执行被哈希的那份字节**（staging）即可消除该窗口。两个对照都实测过。
- **未决缺陷**：`canonical_digest` 覆盖了整个 outcome 载荷，其中包含 `interpreter.version`，而检查器**从不比较** `interpreter` 块。后果是同一个 `E*` 在 `python3.14` 下被**判 FAIL**，`delta = 0.0`、14 行全是 `MISMATCH_DIGEST`。两名验证者各自独立复现，其中一位还把同一根因塞进 conformance runner 复现（对四套适配器当前是**潜伏**的，因为它们都 pin 了 `E_STAR_PYTHON`）。**这是决策项 D1**——一个会在解释器漂移时误杀合法评测器的检查器，与一个会放过变异评测器的检查器同样有害。

### 2.4 `ModelRouteContract`

四条声明（codex→`/v1` `wire_api="responses"`、claude→`/anthropic`、kilo→OpenAI 兼容、opencode→OpenAI 兼容），字段覆盖 provider/endpoint/requested model/API/params/CLI/prompt/tools/permissions/network，外加 runtime/adapter commit 与任务快照。用户决定已编码：`primary=deepseek-flash`、`mixed_secondary_allowed=true`、`permitted_secondary=[deepseek-v4-pro]`、`excluded_providers=[openrouter]`。每条声明带 `identity_evidence`（按协议面逐行记录"请求的 id"与"回声的 id"），并明写**权重级身份无法独立验证**——因为回声不等于证明。

**验证者第一轮把它判为 PARTIALLY**：四份声明里的 `adapter_source_sha256` 与仓库中 106,768 个文件**全都对不上**——它们原本是硬编码字面量。这在一门专门研究"声明身份 vs 实际身份"的项目里正是被研究的那个缺陷类别。现已改为可复算：`sha256(域分隔前缀 ‖ canonical_json([[path, sha256(字节)], …]))`，文件列表取自 `git ls-tree -r <commit> -- <root>` 的升序路径，每条声明自带原像清单与规则。验证者用**自己写的代码**重算，四值四 `MRC*` 全部复现，并证伪了规则（颠倒顺序会变、改一个字节会变、同内容不同 commit 不变——内容寻址，正确）。自测 44/44、14 个负例各按其码退出。

覆盖面声明经复核为**正向准确、枚举不全**：摘要只覆盖 adapter 包，而遗漏清单里没列出同样在包外的 tracked 文件（如 kapso 的 `config/`、`contract/`、`bin/`，eve 的 `tools/`、`steps/`、`selection/`，loreley 的 `src/loreley_a0_plugin*.py` 等）——**小项，见 §4**。另外已明确：`Tools`/`Permissions` 只受 `MRC*` pin 保护，`frozen_routes.json` 不管它们，A1 必须比较 `mrc_star`，没有第二道防线。

### 2.5 观测等价：变异评测器真的构造出来了，而且通过了现有检查器（最高信息量）

`E'` 是 `E*` 的副本加三处语义偏离（M1 审计抽样忽略 seed；M2a/M2b 边界与重叠判定改为无 EPS 的严格比较；M3 边界余量改为对全部圆计算）。在**冻结 theta** 下它与 `E*` 在 `C*` 全 14 个候选上**逐位一致**（`exit_code`/`status`/`failure_kind`/`objective` 的 float bits 相同，结构字段也相同），而在 `fidelity=fast` 的 theta 下**分歧**（`c05`：`ok` → `invalid`）。

- **行为检查器接受它**：`eplus_mut_claim`（执行 `E'` 但上报 `E*` 的身份）→ **PASS，11/11 检查通过，`E-r-equals-E-star` 14/14**。另有三种模式值得记：`omit`（干脆不报身份字段）也 PASS——因为比对被 `if obs.get(...) and table.get(...)` 守卫，**缺失即跳过**；`twin`（被问 c01 却评 c03）也 PASS，因为两者数值位相同。唯一抓住它的是 `E_star-manifest-echo`，而那条通道被检查器自己称为"bonus、非失败"——**正是最可疑的那类 runtime 最不会主动提供它**。
- **证明书拒绝它**：`Q3 REALIZATION NOT_REALIZED`，exit 3。
- **架构性结论（R5）**：就当前设计而言，**没有任何带内证据能关闭 `E'` 这一类**——因为调用 `E*` 的是**适配器**，它报出来的身份是"陈述"而非"测量"。要关闭，必须把 A0.1 行的评测器调用搬进 harness，并让身份成为 **harness 度量的必需字段**（缺失即失败）。变异报告里还有 R1–R7 七类残余等价类，各带"什么证据能抓住它"。
- 报告还给出一个**上界测量**：`E_STAR.json` 里每个候选本就带冻结的 `fast_tier`，而检查器从不使用它；把它纳入比较能抓住本 fixture 的变异，但作者另造了一个"只保留 M2+M3"的兄弟变异 `e_prime_fulltheta`，它在 full 与 fast **两个 theta 类下、全部 14 个候选上**的行为键逐字节相同（只差身份字段），据此说明**加 theta 只是把行为网织密，不能封闭该类**——这与审查第 6 条的判断一致。

### 2.6 KAPSO 两轮 bridge：seam 与真实 campaign 接上了

`verify.py` → `bridge_verified`，12/12 检查通过。第一轮的改善**可判定**：基线 `main` 上是冻结的 `c02_baseline_upstream`（新跑的独立 `E*` = `0.25`），第一轮装上 `c04_near_tie`（提交的 `solution.py` sha256 等于冻结的 `DataManifest` 摘要），记录分 `2.451820520843313`，**裕度 `2.201820520843313`**（相对 `1e-9` 的 epsilon 有十二个数量级）。第二轮在**新进程**中恢复 campaign（`import_from_checkpoint`）后：`_select_parent` 被实测触发并返回第一轮的节点；node 1 的 `parent_node_id=0`、`parent_branch_name=generic_exp_0`；`git merge-base generic_exp_0 generic_exp_1` 恰为第一轮分支的 tip，且第二轮 HEAD 以它为父；第二轮会话自己第一条 shell 命令 `cat solution.py` 看到的就是第一轮的 2808 字节产物；KAPSO 记录的 `code_diff` 恰是 `c04_near_tie → c01_good_hex` 那一行半径。deliverable 也由 KAPSO 自己的选择器定为 node 1。

两条值得注意的副产物：**`EID_r = manifest:1c6cdec3…` 与受审的 A0.1 运行完全一致**——即这次 campaign 是在审计签过字的那把尺子下跑的；成本 22,447 token（不到一分钱），每轮约 20 秒。
**作者自陈的边界（我们确认其表述准确）**：第二轮之前历史里只有一个已完成的节点，所以 `parent_policy=best` 对任何分数都会选中它——这次跑通了 `E* → node.score → node_history → _select_parent → parent_branch` 的真实通路，但**没有**证明"是分数值而非存在性/新近性"驱动了选择。区分分数与延迟需要第二轮之前有 ≥2 个已完成节点。A0.2 的 seam 场景仍是"选择跟随分数"的证据，这个 bridge 是把核接到真实 campaign，不是取代它们。

### 2.7 闭包：在封闭网络里跑通了真实 tool-loop

codex lane 在封闭网内被真实驱动（10,519 token、7 次 shell 工具调用、exit 0），SimpleLoop 同理；agent 写的探针在网内测得：DNS 解析失败、直连/侧向 TCP `[Errno 101]`、代理对未白名单主机的 `CONNECT` 返回 403、对白名单端点返回上游 401（即端点真的通）、候选子进程可跑。**代理自己的决策日志**给出同向佐证（`POST /v1/responses` 200×4，以及对越权目标的 DENY）。为 codex lane 补 `/v1/responses` 路由是**必要**的（未改的共享代理返回 `(None,None)`），该改动只在本次工作流自己的目录里。

**验证者发现并已被修掉的一处**：CONNECT 白名单只匹配主机、不匹配端口，`CONNECT api.deepseek.com:25` 也回 `200 Connection Established`。修前实测显示 `:25`/`:80`/`:8443` 全部 200，其中 `:25` 完成了带真实证书的 TLS 1.3 握手，`:80` 回了一个明文 302——所以"TLS 让它无所谓"是错的，已把规则收紧为 host:port（`PROXY_ALLOW` 里裸主机仍等于 `:443`），修前修后对照表与代理日志都存档。**闭包结论不变**：可达主机集合从未扩大。

## 4. 需要你决策

- **D1（语义）**：`canonical_digest` 是否应包含 `interpreter` 块？建议 (a) 把 `interpreter` 从比较用的 digest 载荷中拆出、**显式比较**并在漂移时给出**独立判定**（"interpreter drift"）而不是伪装成 `E_r disagrees`。当前行为会误杀合法评测器。
- **D2（门槛）**：A1 用 `T_strict` 还是 `T_literal`？即 EvE/Loreley 的 E2E 仍 `UNPROVEN` 时能否进入 A1 主臂。建议：主臂 `T_strict`，`T_literal` 只用于明确标注的 pilot。
- **D3（架构，成本最高、收益最大）**：是否采纳"**把 A0.1 的评测器调用搬进 harness，身份由 harness 度量、缺失即失败**"？这是把 `E'` 这一类从"免费通过"变成 FAIL 的唯一途径；代价是要改 reader 与 `adapter_contract.md`，并重跑一次 A0.1（无需重跑 A0.2）。
- **D4（可复现性 vs 不改被测对象）**：EvE 的采样 RNG 未播种。固定种子需要**改 EvE 代码**；不改代码的替代是"固定 population/config/分数向量，重复整轮"，用轮级重复替代种子固定。
- **D5（清理与轮换）**：`a0pc-*` / `a0tl-*` 容器与两个 internal 网络仍在跑（各有 `teardown.sh`）；`~/.claude/settings.json` 仍是明文 key + 一个自称过期的模型别名（我们未改）；`~/gptapi.md` 的四个明文 key 已进入本会话记录。
- **D6（A1 的真正前置）**：A1 的任务选择、`B_hard = (T_wall, N_evaluatorCalls, concurrency cap)`、预注册正对照，以及各臂的随机交错执行顺序。

小项（不需你决策，除非你想改方向）：MRC §7 缺漏清单补全；`loreley`/`simpleloop` 适配器硬编码宿主根路径。
