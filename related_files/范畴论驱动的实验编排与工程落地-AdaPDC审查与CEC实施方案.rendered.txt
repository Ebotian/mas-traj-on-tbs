范畴论驱动的实验编排与工程落地：AdaPDC 审查与 Compositional Experiment Calculus 实施方案
执行摘要。 结合你当前提交的 adapdc-src-review-72f4b8f.tar.gz 与截至 2026 年 9 月的相关理论、论文和开源实现，我的判断是：AdaPDC 已经不是“概念原型”，而是一个相当扎实的 pre-categorical research runtime substrate；真正缺失的是位于 DSL 与冻结执行 Plan 之间的 categorical semantic kernel。

不建议推倒现有实现重写。 当前已经建立的 content-addressed artifacts、冻结 signatureRef/typeRegistryRef/runtimeRef、Temporal durability、completion manifests、Catalog/reconcile、失败语义和幂等边界，正好是范畴论 IR 最难从数学模型获得、却必须由工程补齐的部分。新的工作应以 ResearchIR v2 → Plan v1 的兼容 lowering 方式叠加，而不是替换 C4。

语义核心建议采用：typed、open、acyclic、monogamous hypergraph 作为 free symmetric monoidal category 的计算表示；复杂实验通过 generators、composition、tensor、symmetry 与受限 graph rewrite 派生，而不是通过 Experiment 对象、继承或不断增加 workflow 特例。 这一表示路线有直接的理论和工程先例：open-hypergraphs、Catlab、AlgebraicRewriting、DisCoPy 以及 string-diagram/DPO 系列论文已经证明了相当多的基础构件。

最关键的工程验证并不是“范畴论是否能表示 workflow”，而是：真实科研变化中有多少能被稳定压缩为“小生成元 + 小边界 + 局部 typed rewrite”。 建议把这个问题设成项目的主验收指标；只有它成立，系统才真正超越“一个数学包装过的 DAG DSL”。

背景、目标与对当前审查包的判断
我们现在讨论的目标已经可以非常明确地写成：

[ \boxed{ \text{TypeScript Surface Syntax} \rightarrow \text{Compositional Research IR} \rightarrow \text{Verified Rewrite} \rightarrow \text{Executable Plan} \rightarrow \text{Evidence / Provenance} } ]

这里最重要的设计决定，是不把 Experiment 设为核心对象。核心 primitive 应当是带有 typed boundary 的 transformation：

[ f:A\rightarrow B ]

两个 transformation 可串接：

[ A\xrightarrow f B\xrightarrow g C \qquad\Rightarrow\qquad g\circ f:A\to C ]

也可以并行组合：

[ f\otimes g:A\otimes C\rightarrow B\otimes D. ]

一次完整 experiment 是这种结构的组合结果，而不是继承体系中的某个实例。这个方向与 string diagram、symmetric monoidal category 以及 open-hypergraph 的计算表示高度一致；2023 年关于 string diagrams 的数据并行算法工作已经给出了基于 structured cospans/ACSets 的计算表示，并研究了 composition、tensor、functor application 等操作的高效实现。

Scope。 第一版不试图形式化“全部科学推理”。它只处理那些能表示成：

[ \text{typed resources} + \text{typed transformations} + \text{composition} + \text{controlled rewrites} ]

的实验结构，包括 baseline replication、parameter sweep、model/evaluator replacement、ablation、数据处理链、指标计算和 evidence derivation。自然语言假设、论文论证、开放式理论推理可以引用到 graph 中，但不要求一开始就成为同一个形式系统。

团队规模：未指定。预算：未指定。 因而下面以 person-week 给工作量，日历时间只给条件性估算。

核心假设有三个。第一，实际科研实验中的大部分“变化”具有局部边界保持性，即可以把一个子实验 (L) 替换成 (R)，而不重写整个 workflow。第二，科学语义所需的 type information 可以压缩成有限、工程上可维护的 facet system，而不需要一开始实现 dependent type theory。第三，现有 executor 不应知道范畴论结构；范畴结构可以先降低为你已经稳定运行的 frozen Plan。

这三个假设都能被实验推翻，因此它们应该成为明确的研究假设，而不是架构信仰。

理论构件、成熟度与相关工程实现
这套架构所需要的数学实际上不是一整套“高阶范畴论”，而是少数几个相当明确的构件。

String diagram rewriting 与 graph rewriting 的对应关系已经有严密工作支持。第一篇 String Diagram Rewrite Theory 将带 Frobenius 结构的 string-diagram rewriting 对应到 hypergraph 上的 DPO rewriting；后续工作处理一般 symmetric monoidal theories，并通过 convex DPO 避免无意的资源复制/删除；DPO with interfaces 又进一步把显式输入/输出 boundary 纳入 rewrite，给出了与局部合流、critical-pair 分析有关的结果。

这对科研 IR 特别重要，因为我们并不希望：

“因为数学上有一个 spider/Frobenius operation，所以数据 artifact 可以默默被复制、合并、删除。”

相反，scientific resources 经常是 provenance-sensitive、resource-sensitive 的。所以第一版建议限制为：

[ \boxed{ \text{typed + directed + acyclic + monogamous open hypergraphs} } ]

也就是基本上保持 free SMC 的 resource-sensitive 语义。

需要复用某个 artifact 时，显式写：

[ A\xrightarrow{\Delta_A} A\otimes A ]

或者在类型上声明该资源属于允许 fan-out 的区域，而不是默认所有 values 都具有无限 copying/deleting。一般 symmetric monoidal theory 中不能无条件复制或丢弃变量，也正是相关 string-diagram rewriting 工作强调的问题之一。

Open-hypergraphs 的官方实现把 operations 表示为 hyperedges、values 表示为 nodes，并保留每个 hyperedge 的有序多输入/多输出以及整个 diagram 的 source/target；这几乎就是我们所需要的 Research IR 数据模型。其 Rust 实现同时提供 imperative builder、data-parallel algebraic operations 和 functors，但项目官方仍把部分接口明确标成 experimental，因此它更适合作为 representation/algorithm 参考实现，而不是 AdaPDC 的直接核心依赖。

一个很重要的工程结论是：没有必要选择其中一个项目然后“把 AdaPDC 移植过去”。

更好的分工是：

[ \begin{aligned} \text{open-hypergraphs} &\rightarrow \text{representation/algorithm reference}\ \text{Catlab} &\rightarrow \text{categorical semantics reference}\ \text{AlgebraicRewriting} &\rightarrow \text{rewrite oracle}\ \text{DisCoPy} &\rightarrow \text{diagram/functor law oracle}\ \text{CQL} &\rightarrow \text{database semantics reference}\ \text{AdaPDC/TS} &\rightarrow \text{production implementation} \end{aligned} ]

也就是说，自己实现一个很小的 TS semantic kernel，但用成熟研究实现做 differential/property testing。

这比把研究软件引入 production dependency chain 更稳。

AI4Science 所处的位置
2026 年的 Experiment-as-Code Labs 已经开始把实验定义成 declarative configuration，再编译为仪器/API 操作，并在系统层讨论 program analysis、safety、resource assignment 和 orchestration。这说明“科研实验应该先成为可分析的声明式程序，再 lowering 到执行系统”正在形成明确趋势。

AI Scientist-v2 则代表另一条主流路线：agent 进行 hypothesis、experiment、analysis 的闭环探索，并用 progressive agentic tree search 管理实验分支。这证明 autonomous experiment search 已经具有工程价值，但它的搜索空间依然主要由 agent/workflow manager 驱动，并不是我们这里的“typed graph rewrite calculus”。

因此，截至目前，我没有在本次审阅的主要原始项目中看到一个已经成熟地同时实现：

[ \boxed{ \begin{array}{c} \text{typed open-hypergraph scientific IR}\ +\text{formal graph rewriting}\ +\text{durable HPC/cloud execution}\ +\text{content-addressed provenance}\ +\text{agent-verified rewrite search} \end{array}} ]

的生产平台。

这正是 AdaPDC 有可能形成独立价值的位置，但也意味着我们应该做一层薄而严格的 semantic kernel，而不是企图一次造完整 categorical platform。

核心原则是：

[ \boxed{\text{ResearchIR} \neq \text{ExecutablePlan} \neq \text{ExecutionRecord}} ]

这三个东西现在必须刻意分开。

ResearchIR 表示“科学变换是怎么组合的”；Plan 表示“这次应怎样执行”；Evidence/Provenance 表示“实际上执行了什么以及产生了什么”。

composition laws 必须真的成为测试，而不只是文档
内核需要直接测试：

[ f\circ id=f ]

[ id\circ f=f ]

[ h\circ(g\circ f)=(h\circ g)\circ f ]

以及 tensor associativity、symmetry、interchange law：

[ (f_2\circ f_1)\otimes(g_2\circ g_1)
(f_2\otimes g_2)\circ(f_1\otimes g_1). ]

但这里有一个实现陷阱：不能要求两边 JSON byte-for-byte 一样，除非我们先定义 canonical normal form。

因此至少区分：

[ \boxed{ \text{content-addressed identity} \neq \text{categorical equivalence} } ]

先把后者用于 law checking，等 canonical graph/isomorphism machinery 成熟后再考虑 quotienting。

Caching
当前 C4 已经明确把 T06 cache variants 留作后续。

建议 cache key 不要包含整个 graph digest，否则：

[ G\Rightarrow G' ]

一次微小 rewrite 就会让所有 node cache 全失效。

正确的 node semantic key 更接近：

[ K_n = H( S_n, I_n, R_n, P_n, A_{1},...,A_k, T_n ) ]

其中：

(S_n)：generator signature digest；
(I_n)：implementation digest；
(R_n)：runtime/environment digest；
(P_n)：canonical parameters；
(A_k)：ordered input artifact digests；
(T_n)：影响执行语义的类型/codec semantics。
示意：

ts
Copy
const executionKey = digest({
  generator: node.signatureRef,
  implementation: node.implementation,
  runtime: plan.runtimeRef,
  params: canonical(node.params),
  inputs: orderedInputDigests,
  codecSemantics: relevantTypeRefs,
});

MVP 验收标准
我建议不要用“实现了 category theory”这种无法验收的句子，而采用：

指标	MVP-A 验收标准
表达能力	五个 benchmark transformation 全部能由 typed rewrite/composition 表示
Change locality	benchmark 中至少 80% 的研究变更不需要修改 executor/runtime
Type safety	curated invalid composition/rewrite suite 必须 100% 在执行前拒绝
Provenance completeness	任一最终 benchmark artifact 都能回溯到 graph snapshot、rewrite chain、plan、generator implementation、runtime 与所有直接输入
Runtime equivalence	现有八节点 deterministic demo 经 v2 lowering 后与 C4 reference execution 得到相同科学结果，并保持既有 frozen semantics
Incrementality	局部 rewrite 不得因 graph-level identity 变化而机械失效所有 unaffected node cache
Immutability	rewrite 后旧 graph digest 及 bytes 永远不变化
Law compliance	identity/associativity/interchange/symmetry property suite 通过
Rewrite auditability	每个 G→G' 有 content-addressed witness
C4 regression	当前 frozen/CAS/manifest/recovery/security checks 不得因 categorical layer 被削弱

这里最重要的项目 KPI 是：

[ \boxed{ R= \frac{\text{可由局部、已验证 rewrite 表达的实际科研变化}} {\text{总 benchmark 科研变化}} } ]

假如真实研究中 (R) 长期只有 20%–30%，那就说明我们把范畴结构放错了层。

如果能稳定达到 70%–90%，并且剩余部分主要是“新增 generator”，那这个方向就很有价值。

风险、替代方案与最终优先级
最大风险其实不是 graph rewriting 太难。

最大的风险是：

我们最后发现真实科学变化并不服从稳定的小边界。

例如实验变化经常同时改变：

text
Copy
data definition
metric semantics
training procedure
comparison protocol
statistical assumptions
如果这些总是强耦合，那么强行写成局部：

[ L\Rightarrow R ]

只会制造虚假的 compositionality。

所以千万不能先把“relation-first 必然优越”当成结论。

这应该由前面那个 (R) 指标验证。

第二个风险是 category-theoretic God Object。

完全可能出现：

text
Copy
一个万能 Category
300 个 Type constructors
1000 个 morphism subclasses
几十种 effects
复杂得没人懂的 rewrite language
那只是把 OOP God Object 换成：

[ \mathcal C_{\rm God}. ]

规避原则应该非常硬：

[ \boxed{ \text{small generators} + \text{small boundaries} + \text{few structural laws} } ]

复杂性必须主要来自 composition。

第三个风险是过早引入 Frobenius/cartesian structure。如果默认所有 values 可 copy/delete，scientific provenance 很容易被隐式结构操作掩盖。MVP 应采用 resource-sensitive core，copy/discard 显式化。相关 string-diagram rewrite 理论正好说明一般 SMC 与自由复制变量之间需要谨慎区分。

第四个风险是 rewrite matching 的复杂度。一般 graph matching 并不便宜，所以第一版不要承诺“对任意大图做任意 rewrite search”。实际策略应是：

text
Copy
small patterns
typed candidate filtering
generator labels
boundary signatures
bounded locality
indexed graph lookup
Agent 甚至可以先指定 candidate region，再由 kernel 验证 match。

第五个风险是 TS surface 与 formal kernel 混淆。TypeScript 很适合人类 API，但它不是 proof assistant。因此：

[ \boxed{ \text{TS static types = ergonomics} } ]

[ \boxed{ \text{frozen runtime contracts = authority} } ]

这与当前 AdaPDC 已经坚持的 frozen signature/type registry 哲学完全一致。

第六个风险是 categorical database scope creep。Categorical DB 和 functorial migration 的确与整个架构非常契合，并已有实际工程研究；但不应因此把 PostgreSQL 重写掉。现有 Catalog 继续做 production fact store，categorical schema/instance model先用于模型设计、migration oracle 或 export。Attributed C-sets 在“图结构与属性数据统一”方面已经提供了成熟研究基础。

第七个风险是把研究级依赖直接变成生产关键路径。AlgebraicRewriting 官方自己明确说仍处于 active development，不能假设稳定 API；open-hypergraphs 也保留 experimental APIs。它们应首先做 reference oracle，而不是系统 availability dependency。

真正的第一道生死 Gate 是：

[ \boxed{ \text{真实 ablation / replication / sweep} \stackrel{?}{=} \text{small typed rewrites} } ]

第二道 Gate 才是：

[ \boxed{ \text{local rewrite} \Rightarrow \text{incremental execution + complete provenance} } ]

第三道 Gate 才让 agent 进来：

[ \boxed{ \text{Agent proposal} \rightarrow \text{formal verification} \rightarrow \text{execution} } ]

如果这三关都成立，那么 AdaPDC 的架构就会从：

“一个做得相当严谨的 typed scientific workflow system”

真正转变成：

“一个可供人类和 AI 操作的、关系优先的 research intermediate representation。”

我认为这是目前最值得追的定义。

最终可以把整个系统压缩成下面这组边界：

[ \boxed{ \begin{aligned} \textbf{Syntax}\quad& \Sigma={\text{small typed scientific generators}}\[3pt] \textbf{Composition}\quad& {id,\circ,\otimes,\sigma}\[3pt] \textbf{Representation}\quad& \text{immutable typed open hypergraphs}\[3pt] \textbf{Evolution}\quad& G\xRightarrow[\text{typed DPO}]{\rho}G'\[3pt] \textbf{Interpretation}\quad& F:\mathcal R\to\mathcal X\[3pt] \textbf{Execution}\quad& F_{\rm exec}(G)\to\text{Frozen Plan}\to\text{Runtime}\[3pt] \textbf{Evidence}\quad& G_0\Rightarrow\cdots\Rightarrow G_n \to P\to E\to A \end{aligned}} ]

其中最关键的一句仍然不是“用了范畴论”，而是：

[ \boxed{ \textbf{Experiment is derived; composition and relations are primitive.} } ]

从你现在的 72f4b8f 审查包看，我认为已经到了可以真正实施这一步，而不是继续停留在理论讨论的时候。当前 C4 最有价值的地方，恰恰是让我们可以在不重新解决 orchestration、CAS、retry、identity、failure/recovery 这些问题的情况下，把接下来的研究精力集中在唯一真正未知的问题上：

[ \boxed{ \text{“Compositional Experiment Calculus 是否确实是科学实验变化的好 IR？”} } ]

这应当成为下一阶段的首要研究问题、工程里程碑和审查包总验收命题。
