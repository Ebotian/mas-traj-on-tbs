# v3 计划:以「可断点重放的轨迹」为实验的最小单位

## 0. 为什么 v3 的核心是这一条

构想着的要求是:**轨迹应当设计成可以断点重放**。这不是加一个工程特性,而是补上 v2 缺的那块地基:

- v2 的对照 —— **share-matched 分配**、**继续 vs 重启 vs 新分支**、**逐步路由 vs 任务级配置** —— **全都要求两条臂从同一个状态出发**。v2 没有规定"状态与轨迹怎么记",于是那些对照要么跑不出来,要么跑出来**不可解释**(差异里混着状态不同)。
- **两个独立来源都指向同一件事**:第 8 轮外部复核的 launch gate 里写着「snapshot/restart mechanism —— paired recovery 实验的前提」「failure-injection API」;本会话的 M0/M1 规格同样要求"冻结环境与预算"。
- **项目里已有实例,不是新概念**:`related_files/conversation/replay_state_control.py` 已把 C 线的补丁链**重放到与已知答案逐字节一致**;kimi-code 把执行状态收进 core 做成**可重放状态机**(以固定提交为证)。v3 要做的是**把已有的做法用到实验上**。

## 1. 一条轨迹的定义(要冻进协议)

**轨迹 = 事件流 + 检查点**。

- **事件流(append-only)**:每一步记 `t · arm · step · 动作 · 工具调用 · token(输入/输出/缓存分桶) · 墙钟 · 产物哈希 · 判据调用与返回 · 决策(谁选的、依据哪条可见信息)`。
- **检查点(在预注册的预算点 `k·B₀`)**:一份**可重放的状态** = 会话状态 + 工作区快照(内容寻址)+ 计量累计 + 事件指针。
- **不变式(最重要的一条)**:从任一检查点分叉出的两条轨迹,**除被指定的自变量外必须逐字节可比**。做不到这一点,后面所有比较都不成立。

## 2. 三条可执行实验(全部靠"从同一检查点分叉")

| 实验 | 从同一检查点分叉出什么 | 读什么 | 杀死条件 |
|---|---|---|---|
| **E1 = M0 仪器检查** | 注入三类产物:①已知正确 ②无改善 ③错误但自称完成 | ③的**误接受率**(另记误拒绝与自述诱导) | ③被接受 ⇒ 仪器不可判别,停止一切比较 |
| **E2 = M1 share-matched** | 任务匹配分配 vs **同份额打乱**分配(+ 单模型基线) | 成功率 / 真实费用 / 墙钟 **分报** | 两者相等 ⇒ 路由不含任务针对性信息 |
| **E3 = 继续 / 重启 / 新分支** | 三条动作,给**等量增量预算** | 每笔增量预算换来的改善、成功概率、等待时间 | 重启不优于继续且更贵 ⇒ 停止规则不成立 |
| E4 = v2 的机制比较(MasRouter / EvoRoute / 决策模型) | —— | 见 v2 | —— |

**顺序:E1 → E2 → E3 → E4。** E4 直接开跑等于在仪器不可读时比较机制。

## 3. 断点重放的最小实现(接线)

- **宿主**:qwen-code(已确认 `-p` 无头可用、`--sandbox`、`--telemetry-outfile` 为计量通道;其无头默认 yolo+无沙盒,试验必须显式钉住)。
- **检查点**:工作区 tar(内容寻址)+ 会话 JSONL + 计量累计。
- **重放器(MVP,先做这一件)**:把「事件流 + 快照」还原成可继续的会话。**验收口径**:同一检查点跑两次,**除时间戳外事件流一致**;再验一次"从检查点分叉两条、只改一个自变量,前缀逐字节相同"。
- **判据**:E1 用**确定性判据**(不接模型判决),同时它就是后续实验的最终评分器候选。

## 4. 相对 v2 的改动(保留 / 修正 / 新增)

- **保留**:三臂(机制层)、四问、统一环境与三个固定执行模型、成本分账、以及它自警的"系统比较 ≠ 纯路由差异"。
- **修正**:①**顺序**改成 E1→E2→E3→E4(机制比较退到最后);②**数据集**按第 17 轮修正为 **LHTB 优先**(它比 DS-1000 更匹配"跨任务类型 + 长程执行");③v2 的系统比较问题由 **E2 的 share-matched** 解。
- **新增(本轮的核心)**:把**轨迹与检查点**列为一等交付物 —— 不是日志,而是**可直接分叉的实验资产**。

## 5. 我的意见:关于「GPT 暂时不可用」

**不必等,但要把风险摆明。**

- **为什么不必等**:v3 的决定性要求(**可断点重放的轨迹**)是**本地座**的活,而且项目里已有两处实例可借;网页座的强项是**对抗性审查**与**广度检索**。现在起草 v3,等于让两座各自做更擅长的**那一半** —— 而不是把推进卡在一条网络上。
- **风险(必须说)**:单座起草**缺对抗**,容易自洽而空洞。补偿三条:①v3 每条都写**杀死条件**(本文件已写);②**E1 先跑** —— 它本身就是"仪器能不能拒绝假进展",对 v3 自己同样适用;③网页座恢复后,**送它审这份 v3**;它接到的将是一份**可执行协议**,而不是又一轮泛泛讨论。
- **接下来的一步(零额度先做)**:装配 E1 的**样本集与确定性判据**(一个固定小任务 + 三类产物 + 判据),跑出③的误接受率。这一步不需要宿主、不需要联网、不花模型额度;它的结果会直接决定 v3 是否需要改。

## 6. 仪器 = 宿主 + 我们的判据 + 计量 + 检查点层(回答"直接用现成最新版开源 agent 够不够")

**够,但只覆盖四件里的一件。** 现成 agent 是**执行器**;把它当**仪器**还缺三件 —— 而这三件都在这份 v3 里。

| # | 要件 | 现成 agent 给不给 | 处置 |
|---|---|---|---|
| 1 | **执行器**(可无头驱动、可冻结) | ✅ qwen-code:`-p` 实测可用;`--sandbox` 可钉 | 直接采用 |
| 2 | **判据**(可执行、确定性、**控制入账**) | ❌ **两者都不给** —— qwen 的 goal-verifier 是**模型判决**;kimi 的 `completionCriterion` 只渲染、**从不求值** | **测试侧自己写**,并作为入账门 |
| 3 | **计量**(token 分桶 / 墙钟 / 工具调用) | ✅ 实测 `--telemetry --telemetry-outfile` 输出含 `input_token`/`output_token`(423 KB 样例) | 直接采用,但要逐运行归档 |
| 4 | **检查点分叉层** | ❌ 无现成 API:qwen 的状态在 host journal + 会话 JSONL(按会话可续,无回合中途快照/分叉);kimi 的 core **本身是可重放状态机**(更接近要求),但未暴露快照/分叉接口;且它的 host 入口在本地 checkout 里**未找到 bin** | **自己写**(§3 的重放器) |

**两条必须钉住的方法论**

1. **harness 是固定因子,不是自变量**。Scaffold Effect 显示:同通过率下不同 scaffold 的每题 token 差约 **40×**。
   若在实验中换宿主,这 40× 会混进每一次对照 ⇒ **E1–E3 固定一个宿主**;等判据与重放层成型后,再把"换宿主"作为**独立的一维**测。
2. **冻结清单**(每次运行逐条记录):宿主版本(固定提交) · 执行模型(型号/供应商/日期) · 工具集与权限 · 沙盒 · 预算(token + 墙钟) · 提示模板 · **判据版本与可见性**。
   特别注意:qwen-code 无头默认是 **yolo + 无沙盒**(其自身打印警告),不钉就不可复现。

**选谁**:E1–E3 **用 qwen-code**(四件里两件已实测;另见 C41:它接受外部 PR 且自跑 SWE-bench 回归)。kimi-code 列为**候选** —— 它的 core 在"可重放"这一点上更接近我们的要求,值得在"换宿主"那一维里优先测。

## 7. MAS 路由:**不是**选模型,而是"协作结构"的路由(2026-10-08 二稿,依构想着更正)

构想着更正:「不是换模型,而是**协作 route** —— 比如在同一轮中以特定组织结构(分工、派发…)进行 MAS,其中 route 是构成 MAS 的**关键子系统**」。
这与 MasRouter 的名字一致:「**route LLMs *for multi-agent systems***」—— 路由的对象是**协作结构**。

**但模型这一维不是可选项(构想着 2026-10-08 再补)**:「不只是每步用哪个模型,因为在我们设想的 mas 中,**允许不同供应商、不同模型配置在同一轮对话中协作**,因此,**不同模型的 route 才必不可缺**」。
⇒ 路由的完整对象是 **(结构 × 角色 × 供应商 × 模型 × 配置 × 信息可见性)**,而**异构性正是 MAS 的定义性特征**:同一轮里就有多个供应商/配置在协作。"模型 route" 因此**是必需的一维**,不是"其中一维"。

### 7.1 现成宿主已经给了什么(qwen-code,均为本会话回源码核实)

| 已给 | 位置 |
|---|---|
| **角色是声明式定义**(不是临时提示) | `packages/core/src/subagents/`:`agent-frontmatter-schema.ts`(frontmatter 定义 agent)、`builtin-agents.ts`、`execution-backend.ts` |
| **派发/停止有管道与可观测点** | `subagent-manager.ts`;hooks 里的 **`SubagentStart` / `SubagentStop`** |
| **后台 agent 可恢复** | `agents/background-tasks.ts`、`agents/background-agent-resume.ts` |
| **并发有上限,且已按模型分槽** | `DEFAULT_MAX_CONCURRENT_BACKGROUND_AGENTS = 10`;`maxConcurrentBackgroundAgents` **与 `maxConcurrentBackgroundAgentsByModel`** |
| **模型运行期可换** | `config.setModel` / `switchModel`(有测试);另有 `advisorModel` + `advisor-policy`(第二个模型在环的先例) |

### 7.2 缺的**正是整个路由器**

**今天"派不派、派给谁、怎么合"是 LLM 自己决定的** —— 委派是一个**工具**:`packages/core/src/tools/create-sub-session.ts`(默认 `ask`,让分类器审)。
⇒ **继承它 = 把路由器变成一个不受控的变量。** 要成为实验套件,必须补上:

0. **宿主在模型维上已经给了什么(本会话核实)**:逐 agent 可绑**模型**(`subagent-manager.ts:197` 的 `{ ...config, model: exploreModel }`;测试里 `model: 'custom-model'` / `model: 'fast'`,另有 `validateModel`),且**逐 agent 可绑配置**(`:1454` 注明 `reasoningEffort`「总是需要自己的视图,即使在父模型上」)。
   ⇒ **异构 MAS 在现有配置面上就能表达**;我们缺的不是"能不能用不同模型",而是**谁来决定这个分配、怎么记它、怎么按供应商分账**。
1. **路由接口**:决定 *结构形式 × 角色**分工** × **供应商** × 模型 × **配置** × 信息可见性* 的分配;**必须可插臂**(MasRouter / EvoRoute / 决策模型 / 基线插同一个插座)—— 这正是 E4 能成立的前提。
2. **分配矩阵逐检查点入账**,其**原子单位是四元组 `(角色, 供应商, 模型, 配置)`** —— 这张矩阵**就是 E2 要打乱的那个单位**(share-matched 打乱的是这个对应关系,不是"每步用哪个模型")。
   注意一条陷阱:**"同一模型名 ≠ 同一 agent"** —— reasoning effort / 上下文长度等配置必须一起入矩阵,否则"换了配置"会被记成"换了模型"。
2b. **计量必须按供应商分账**:DeepSeek 的缓存桶与未命中相差 **50×**、GLM 的缓存是输入的 25% ⇒ **单一 token 计数无法比较异构臂**;`Φ_θ` 必须按 `(供应商, 模型)` 化(见 `economics-of-agent-systems-2026-10-08.md` 的三张价目)。
2c. **并发要按供应商/模型排程**:`maxConcurrentBackgroundAgentsByModel` 是现成抓手;异构供应商的速率与延迟不同 ⇒ 路由的分配必须在这组上限下**可行**。
3. **聚合事件**:合并/汇总那一步必须是一条事件 —— 判据判的是**聚合后的产物**。
4. **中和宿主自带的委派**:把工具集钉住,使**模型不能自行 spawn**;否则路由器的分配会被模型自己的选择污染。

### 7.3 结论:改,但改的是"路由器 + 分配日志 + 聚合事件",不是重写成一套 suite

- **宿主保持为固定因子**,并**版本戳**(改过的宿主是一个**新的 scaffold** ⇒ 必须重新基线;Scaffold Effect 的 40× 就在这条线上)。
- **路由器策略 / 判据 / 检查点层放在我们自己仓库**作 sidecar:判据不能是宿主自带的判官(自指),检查点层与宿主无关(保留"换宿主"那一维的便宜)。
- **只补一个缝**:委派路径(`create-sub-session` / subagent spawn)改由**路由器**决定,且每次 spawn/合并都入事件日志。
- **换来什么**:E2 的 share-matched 从"说不清"变成**良定义**(固定**份数**,只打乱角色×模型×信息的对应);E4 的三臂插同一插座 ⇒ 比较的是**策略**,不是系统 —— 这正是 v2 自己警告过的(「完整 MasRouter 与完整 EvoRoute 的比较属于系统比较」)。

### 7.4 待构想着定:套件放哪里

建议:**套件独立成一个本地目录**(钉住 qwen-code 的 commit),`rsi-dev` 只留**规格 / 判据 / 事件日志 schema / 结果**(纯文本,与语料纪律一致)。理由:宿主代码体量大且会漂,放进来会让语料失真;而"实验资产"该是可重放的小东西。

## 8. 拓扑不是前提,是变量(2026-10-08 三稿,答"是不是必须有父模型/进程树")

构想着问:「目前来说,貌似我们的使用过程还是单供应商单模型的,是不是必须存在一个父模型作为根模型,之后像进程树一样?**这是我们希望的协作结构吗…?**」

### 8.1 先拆一个混同:"根模型"其实把三个角色捆在一个节点上

| 角色 | 干什么 | 能不能分离 |
|---|---|---|
| **派发/规划** | 决定分几步、派给谁 | 能(可以是弱模型、也可以是规则) |
| **聚合** | 把各支的产物合成一个可判的产物 | 能(可以是另一节点,甚至是确定性代码) |
| **权威/判决** | 说"完成/继续"、控制入账 | 能(**且必须**由我们的测试侧判据担任 —— 见 §6/§7) |

一棵"根 + 子树"的进程树把这**三件合成一个节点**。⇒ **"有没有根"其实是一个假问题**;真问题是这三个角色**由谁承担、是否允许分离**。
分离恰恰是实验最值得测的东西(例如:弱派发 + 强验证 vs 同节点全包)。

### 8.2 直接回答:不是必须,而且不该预设

- **E1 根本不需要根**:E1 = 同一检查点注入三类产物、看判据的误接受率 —— 一个工作者 + 我们的判据就够。**先有根反而把 E1 复杂化。**
- **拓扑的有效性是任务相关的(有外部证据)**:MARBLE(arXiv:2503.01935,**论文原文我已核到摘要级**)原文是「graph structure performs the best … **in the research scenario**」,即**任务内**结论;报告把这点转述为「拓扑优势是任务相关的,不是普遍主张」。
- **"先定树"会把变量提前锁死**:对话材料里的「方向 2」(信息 × 编排的 2×2 交叉)正是为了测"**结构本身**有没有额外贡献";若一开始就钉成进程树,这个变量就在测量前消失了。
- **证据分级(依 AGENTS.md)**:「MasRouter 把协作形式列为路由对象」目前只有**对话转述**(v2 协议那轮),我**未读其正文** ⇒ 标记为【转述】;可核的只有它的编号与标题(`2502.11133v1`)。

### 8.3 那"我们的使用过程还是单供应商单模型"这句,要分两层看

- **每个座位是单模型**:本地座 = `deepseek-v4-flash`(settings 里还配了 qwen/glm/kimi 等条目);网页座 = GPT-6。⇒ 座位内单模型,这是事实。
- **但整个单元已经是异构的**:同一任务上,**不同供应商的两个模型 + 一个人**在协作(分工与权威结构也已存在:构想者是粗选者,本地座做工,网页座做对抗审查)。
  ⇒ **我们现有单元本身就是一个 MAS 实例**,只是它的结构**不是树**、而是"人—本地—网页"的三方回路。这句话值得记住:**别把实验对象的结构,误当成我们自己协作用的结构** —— 两者可以不同,而且我们的回路已经提供了 E1/E2 的现成经验。
