# 1. 数论 Number Theory — 31 项，16 项有 L

1. **001 [–] Milne rationality conjecture**：证明阿贝尔簇良好约化下 Milne 有理性猜想；与 032 联合，还声称能以同一个有理代数循环同时实现各种 ℓ-adic 与 crystalline realization。
2. **002 [–] 低 Selmer corank 下完整 BSD 公式**：对某素数 \(q\) 的 \(q^\infty\)-Selmer corank 为 0 或 1 的椭圆曲线，给出完整 Birch–Swinnerton-Dyer leading-term formula，并推出 Tate–Shafarevich 群有限。
3. **003 [L] Quasi-Riemann hypothesis**：声称所有 Dirichlet \(L\)-函数在 \(\Re s>7/8\) 无零点，包括 \(\zeta(s)\)；还扩展到 \(\mathbb Q(\sqrt{-3})\) 上有限阶 Hecke \(L\)-函数。这个 family 的 Lean scope 我专门看过，确实把 \(7/8\) 非零区域写进了形式化目标。
4. **004 [–] Hilbert 第十问题 over \(\mathbb Q\)**：声称证明不存在算法判定整数系数多项式是否有有理零点，即给出长期开放的 \(H10(\mathbb Q)\) 否定答案。
5. **005 [L] Catalan 常数无理性**：证明
   \[
   G=\sum_{j\ge0}\frac{(-1)^j}{(2j+1)^2}
   \]
   是无理数；Lean scope 明确对应的就是这一本体结论。
6. **006 [–] Goldfeld 猜想**：二次 twist 的解析秩 0、1 各密度 \(1/2\)，平均解析秩趋于 \(1/2\)；与 002 联合会给出密度 1 的 twists 上完整 BSD。
7. **007 [L,R] two-point Chowla / corrected Elliott**：普通平均意义下解决二点 Chowla，并给 Liouville correlation 一个对数幂节省；进一步处理二元 corrected Elliott conjecture。
8. **008 [L] Deligne–Drinfeld conjecture**：声称 Grothendieck–Teichmüller Lie algebra 在 Ihara bracket 下由每个奇权 \(3,5,7,\ldots\) 的一个生成元自由生成。
9. **009 [L] Milnor \(K\)-theory / Galois reconstruction**：由 \(K_1^M/\ell,K_2^M/\ell\) 及乘法结构重建高超越次数函数域，并处理 Bogomolov–Pop reconstruction。
10. **010 [–] \(p=2\) 的 Fontaine–Mazur / pro-modularity**：处理此前最棘手的 dyadic 情形，包括二维 2-adic Galois representations 的 classical modularity/pro-modularity。
11. **011 [–] \(p-1\) 的素因子统计**：声称证明 prime predecessor 的归一化素因子大小趋向 Poisson–Dirichlet \(\mathrm{PD}(1)\)，并有 Euler totient fiber 的强结果。

## 怎样理解这批东西的“真实性等级”

这里有一个很容易被新闻标题弄坏的逻辑层次：

\[
\boxed{
\text{manuscript exists}
\;\not\Rightarrow\;
\text{proof correct}
\;\not\Rightarrow\;
\text{formalization matches intended theorem}
\;\not\Rightarrow\;
\text{community-understood theorem}
}
\]

Lean 极大提高了第一道**形式正确性**门槛，但仍有两个重要问题。

其一是 **statement correspondence（形式化命题是否准确表达论文真正声称的数学命题）**。这正是 Comparator artifacts 有意义的地方；例如 003 的 `lean/docs/003.md` 明确写出了 scope，把 Dirichlet \(L\)-function \(7/8\) zero-free region 与 paper 对应起来，这比仅仅扔一个 Lean 文件可靠得多。但整个仓库的 formalization metadata 仍标成 `Partial progress` 和 `unchecked`。citeturn340076view0turn340076view2

其二是 **human mathematical understanding**。AGMAI 昨天的声明说得很准确：这个 release 是“beginning, not completion”——即使 proof checker 接受一个 artifact，数学共同体仍需理解其关键机制、检查形式化边界、把它与已有 literature 接起来，并判断哪些是真正新颖的思想。AGMAI 明确不把自己的 advisory role 解释为对结果的 endorsement。citeturn548725search1turn548725search5

所以，我现在对这次 release 的判断是：

**从“AI 数学研究能力”角度，这批材料即使最终只有相当一部分成立，也已经是一次非常大的相变信号。** 它不像过去那种“单个 Olympiad benchmark 提升”或“偶尔解决一个开放问题”，而更像一个系统同时横跨数论、TCS、组合、分析、几何、概率、PDE，在大约 4,000 个开放问题尝试中产出 372 个被筛选为有意义的 result families。OpenAI 给出的平均成本约为每个 result 相当于 3 小时 ChatGPT Pro thinking compute。citeturn358197search15turn358197search11

但从“数学知识已经更新了多少”角度，**今天还太早**。尤其是 topology、algebraic geometry、部分 number theory 中那些无 Lean 的巨大主张，我会暂时写成：

\[
\text{high-value candidate theorem}
\quad\text{而非}\quad
\text{established theorem}.
\]

反过来，像 **003、005、007、017、087、102、159、197、221、271、287、362** 这些既有形式化材料、部分还有 reasoning trace 的 family，是目前最值得优先下钻的样本。其中 003（quasi-RH）、017（\(\mu(\pi)=2\)）、087（Mahler）、102（UGC）、197（Kaplansky direct-finiteness 反例）、287（free group factors）、362（Vlasov–Maxwell）基本覆盖了不同类型的“AI 如何真正做出新数学”的代表机制。citeturn358197search11

还有一个相当值得注意的元结论：**这 372 项不是 372 次独立 one-shot miracle。** README 明确说有些结果建立在模型先前结果之上，而且 family 内部会包含 principal result、companion argument、consequence、alternative proof。换句话说，已经能看到一种你之前一直在讨论的 **research graph / chain-of-action** 现象：模型不是只回答问题，而是在已经得到的 theorem 上继续长出 lemma → generalization → consequence → alternative proof。这个我认为比“722 篇”这个宣传数字本身更值得研究。citeturn358197search11 memcite

如果把这批 release 当成一个大型实验，而不是新闻，我认为下一步最有价值的是**系统审计这 10 个 reasoning-trace family：从原开放问题 → model reasoning → manuscript → Lean statement → Comparator correspondence → 真正新 lemma → 对已有 literature 的依赖，逐条重建其研究过程**。这样才能回答更有意思的问题：这个 internal model 到底只是“极强 proof searcher”，还是已经出现了你关心的那种**可连续构造研究对象、生成中间理论并反复利用的 autonomous mathematical research loop**。

### 2. 对 multi-agent 最直接的启发：优化相关性，而不是 \(N\)

我们之前的沙箱分析已经有：

\[
N_{\mathrm{eff}}
\approx
\frac{N}{1+(N-1)\rho}.
\]

若 agent 输出高度相关，\(\rho\to1\)，则即使开 20 个 agent：

\[
N_{\mathrm{eff}}\approx1.
\]

也就是说：

> **五个“同模型 + 同 prompt + 同检索源”的 Agent，通常不是五倍搜索。**

`openai/math` 有意思的地方在于，同一 family 会出现不同 proof、companion result、formalization 等不同路径。这提示我们的组合优化应该主动制造 **orthogonal search operators**：

\[
\begin{aligned}
A_1 &: \text{direct construction}\\
A_2 &: \text{counterexample search}\\
A_3 &: \text{numerical experiment}\\
A_4 &: \text{constraint/solver approach}\\
A_5 &: \text{literature-derived transformation}\\
A_6 &: \text{formal verification}
\end{aligned}
\]

而不是让六个模型都“再想一遍”。

我们真正应优化：

\[
\boxed{
\max_S
\;
\text{Expected Gain}(S)
-
\lambda C(S)
-
\gamma\,\text{Redundancy}(S)
}
\]

例如简单写成：

\[
J(S)
=
E[Q(S)]
-\lambda\sum_{i\in S}c_i
-\gamma\sum_{i<j}\rho_{ij}.
\]

这比“多少 Agent 最好”是更合理的问题。

你之前报告里得到的结论也是这个方向：真正重要的不是 raw \(N_{\rm agents}\)，而是有效独立信息源数量。fileciteturn29file0L15-L22

### 3. 对计算优化更重要：可以做 **Value of Computation routing**

这是我觉得现在最值得在 OPL 里真正实现的东西。

假设现在有一个算法优化任务，当前状态为 \(s_t\)。

下一步并不是固定：

> Think → Search → Code → Test

而是允许：

\[
a_t\in
\{
Think,
Search,
Retrieve,
Experiment,
Spawn,
Verify,
Formalize,
Stop
\}.
\]

为每个动作估计：

\[
VOC(a\mid s)
=
E[\Delta U\mid s,a]
-
C(a).
\]

于是：

\[
a^*
=
\arg\max_a VOC(a\mid s).
\]

若

\[
\max_a VOC(a\mid s)<0,
\]

则应停止计算。

这解决了现在 Agent 最常见的一种浪费：

> 已经有 95% 把握了，还继续 thinking 20k tokens；  
> 或已经明确需要实验，却继续让语言模型空想。

你之前的实验已经观察到：继续计算可以继续降低 regret，却因为 compute cost 导致**净效用反而下降**。fileciteturn29file0L15-L22

`openai/math` 的规模化研究反过来提供了一个很好的现实范式：

\[
4000\ problems
\to
candidate\ outputs
\to
family\ aggregation
\to
formalization
\to
verification.
\]

它不像传统 benchmark：

\[
prompt\to answer.
\]

而更接近：

\[
\boxed{\text{budgeted research search}}
\]

这才是我们真正应该模拟的东西。

### 4. Lean 对我们的启发甚至比模型本身还大

为什么数学可能特别适合 Agent scaling？

因为数学有一个梦幻条件：

\[
\boxed{\text{generation expensive,\quad verification comparatively cheap}}
\]

Lean 就是 verifier。

模型可以大量探索：

\[
x_1,x_2,\ldots,x_N
\]

然后 verifier 给：

\[
V(x_i)\in\{0,1\}.
\]

这时 parallel search 特别容易扩展。

而我们做算法优化，也应该人为制造类似 Lean 的东西。

例如一个算法优化节点，不接受：

> “我认为这个方案应该更好。”

而要求：

\[
Artifact=
(
code,
benchmark,
seed,
dataset,
metric,
constraints,
result
).
\]

然后自动 verifier：

\[
V(Artifact)
=
\begin{cases}
1,& tests\ pass\\
0,& otherwise
\end{cases}
\]

再加 numerical evaluator：

\[
Q(Artifact)
=
(score,\ runtime,\ memory,\ robustness).
\]

这样 Agent search 才真正有“物理世界”。

所以对 ADA 来说，我反而会把一项优先级提得非常高：

\[
\boxed{\text{Verifier Adapter Layer}}
\]

把：

- unit tests
- property-based tests
- numerical tolerances
- benchmark harness
- constraint solvers
- simulators
- Lean / SMT
- static analysis
- metamorphic tests

全部统一成一种 verifier interface。

没有 verifier 的 multi-agent 很容易变成：

\[
\text{多个语言模型互相评论语言模型}.
\]

那种结构我现在越来越不看好。

## 所以 ADA / OPL 我会怎么调整

我们之前给 Agent Engineering 分出的七个理论域里，已经特别强调了 **Search & Computation、Coordination、System Identification**，而现阶段最缺的也正是 Decision-Sufficient State、Adaptive Observability、Failure/Recovery Dynamics 等基础量。fileciteturn29file0L24-L39

现在结合 `openai/math`，我会让两个项目更明确地分工：

**ADA = research dynamics environment**

负责：

\[
\begin{aligned}
&Artifact\ DAG\\
&Experiment\ execution\\
&Verifier\ adapters\\
&Provenance\\
&Cost\ accounting\\
&Agent/tool\ telemetry\\
&Replay\\
&Counterfactual\ evaluation
\end{aligned}
\]

而 **OPL = metacontroller / research policy**

负责：

\[
\begin{aligned}
&\text{Which node to expand?}\\
&\text{Which operator?}\\
&\text{Which model?}\\
&\text{How much compute?}\\
&\text{Parallel or sequential?}\\
&\text{When to verify?}\\
&\text{When to merge branches?}\\
&\text{When to stop?}
\end{aligned}
\]

于是 OPL 真正优化的是：

\[
\boxed{
\pi(a_t\mid s_t)
}
\]

ADA 则提供：

\[
s_{t+1}=F(s_t,a_t,\xi_t)
\]

和观测数据。

这一下就从“Agent framework”变得很像一个真正的 **control / operations research problem** 了。

---

而且我觉得这里有一个挺有意思的变化：我们之前还在问“Agent engineering 有没有类似空气动力学里的状态量和稳定性导数”。现在 `openai/math` 给我的感觉是，**我们可能已经看到一个可以实验辨识这些量的足够复杂的系统原型了**。你之前报告最后提出从 \(T_1,T_2,T_7\) 开始寻找状态量、局部响应系数、operating envelope 和 similarity law，我现在反而更赞成这条路线了。fileciteturn29file0L39-L53

下一步甚至不需要再写大综述。最有价值的实验可以很小：**固定一个真实算法优化任务和总 compute budget，对比 single-agent、同质 swarm、异质 swarm、family-graph search、VOC routing 五种策略，并测量 \(N_{\rm eff}\)、单位 compute 改善、branch survival、reuse gain 和最终 Pareto frontier。**

还有一个我认为必须吸收的“反面教材”：2026 年有人专门审计 GSO、SWE-Perf、SWE-fficiency，发现**性能优化 benchmark 本身可能非常不稳定**。例如它们跨机器重复运行后，仍始终满足原 construction rule 的任务分别只有 39/102、11/140、411/498；不同 scoring rule 甚至能显著改变同一批模型的排名。citeturn621283search5turn621283academia24

这件事对我们很重要，因为以后如果 ADA/OPL 宣称：

\[
Agent_B > Agent_A,
\]

至少要先分解成

\[
\underbrace{\Delta_{\rm agent}}_{\text{真实策略差}}
+
\underbrace{\epsilon_{\rm env}}_{\text{机器/环境噪声}}
+
\underbrace{\epsilon_{\rm scorer}}_{\text{评分函数偏置}}
+
\underbrace{\epsilon_{\rm sampling}}_{\text{任务抽样}}
.
\]

否则我们会很容易“优化 benchmark”，而不是优化 Agent。

我现在会把我们的总评测状态写成一个**七维向量，而不是一个总分**：

\[
\boxed{
Y=
(Q,P,R,C,H,M,V)
}
\]

其中 \(Q\) 是 **verified outcome quality**，例如 success、F2P、P2P、speedup、memory；\(P\) 是 **progress/search dynamics**，例如 best-so-far curve、AUC、cost-to-threshold、stall ratio、replan latency；\(R\) 是 **reliability/recovery**，例如 pass\(^k\)、方差、restart parity、recovery loss；\(C\) 是 **compute/resource cost**，包括 token、tool call、wall time、GPU、美元；\(H\) 是 **human attention**，例如每个 accepted outcome 消耗多少人工分钟、多少次纠正/授权；\(M\) 是 **multi-agent composition**，这是我们自己的重点；\(V\) 则是 **evaluation validity**，包括 verifier isolation、cross-machine stability、treatment parity、contamination、score sensitivity。

其中 \(M\) 我觉得应该比现有 benchmark 做得更深。我们已经有

\[
N_{\rm eff}\approx
\frac{N}{1+(N-1)\rho},
\]

下一步可以实测每个 Agent 的 **marginal contribution**：

\[
MC_i
=
Q(S)-Q(S\setminus\{i\}),
\]

再做 cost-normalized：

\[
CE_i
=
\frac{Q(S)-Q(S\setminus\{i\})}{C_i}.
\]

两个 Agent 的冗余则不只看文本相似度，而应看**搜索路径/实验结果的条件相关性**：

\[
\rho_{ij}
=
\operatorname{corr}(\Delta Q_i,\Delta Q_j\mid s).
\]

于是某个 Agent 即便自己平均 score 不高，如果

\[
MC_i>0,\qquad
\rho_{ij}\ll1,
\]

仍可能是非常好的 swarm component。这比“哪个模型 benchmark 分高”更接近组合优化。

同样，对于优化过程，我很建议把最终分数 \(Q_T\) 降级为一个指标，再新增：

\[
AUC_Q(B)
=
\frac1B
\int_0^B Q^*(c)\,dc,
\]

其中

\[
Q^*(c)=\max_{c'\le c}Q(c').
\]

它表示**预算 \(B\) 以内一路获得了多少有效进展**。两个 Agent 最后都做到 0.80，但一个 \$2 就到 0.78，之后缓慢优化；另一个 \$20 前一直 0.2，最后突然 0.80，它们在工程上显然不是同一个系统。

对应地，再定义

\[
C_\tau
=
\inf\{c:Q^*(c)\ge\tau\},
\]

即 **cost-to-threshold**。这和 METR 的 expenditure horizon 是同一类思想，但我们可以直接用于 algorithm optimization。

我还会加一个很关键的量：

\[
L_{\rm recovery}
=
Q_{\rm counterfactual}
-
Q_{\rm after\ failure/restart}.
\]

也就是 **recovery loss**。然后人为注入 context truncation、agent crash、tool error、wrong branch、stale evidence，再看多久恢复。这种实验比单纯“跑 100 个正常任务”更容易辨识 Agent system 的动力学参数。

所以对 ADA/OPL 的实现，我现在反而很明确：

**ADA 不应该先实现一个大而漂亮的 benchmark suite，而应该实现一个统一的 measurement substrate。**

每个 action/branch/experiment 至少产生：

\[
(
state,\,
action,\,
agent,\,
cost,\,
observation,\,
artifact,\,
verifier,\,
progress,\,
failure,\,
recovery
).
\]

然后 OPL 在这个 substrate 上比较：

\[
\pi_1,\pi_2,\ldots,\pi_k
\]

的控制策略。

这也意味着我们第一轮真实实验不必很大。选一个有确定 verifier 的算法优化问题，固定 model 与总预算，只改变 orchestrator：

\[
\text{single}
,\quad
\text{homogeneous swarm}
,\quad
\text{heterogeneous swarm}
,\quad
\text{VOC routing}
,\quad
\text{graph/family search}.
\]

然后不只看最终 \(Q\)，而同时比较

\[
(Q,\ AUC_Q,\ C_\tau,\ pass^k,\ recovery,\ H,\ N_{\rm eff},\ MC_i).
\]

这样第一次实验就已经能回答一些很硬的问题，例如：

\[
\text{多 Agent 的收益究竟来自并行 compute，还是信息多样性？}
\]

\[
\text{多花的 \$1 预算到底应该给同一个 Agent 深思，还是 spawn 一个低相关 Agent？}
\]

\[
\text{什么时候继续搜索已经进入负 VOC？}
\]

\[
\text{哪一种拓扑在相同预算下有最高 useful-work density？}
\]

这比“再造一个 Agent 框架”有价值多了。

我现在甚至倾向把 **LoopX + LHTB + KernelBench/SWE-efficiency + METR expenditure horizon + τ-bench/MultiAgentBench** 看成五块互补拼图：LoopX 给过程控制指标，LHTB 给长程 trajectory，Kernel/SWE 给真正的 optimization objective，METR 给经济尺度，τ/MultiAgentBench 给稳定性与组合结构。把这些吸收到 ADA 的观测层，我们之前说的 **Agent System Identification** 就会从一个抽象研究设想，变成一个非常具体、可实验的工程计划。
