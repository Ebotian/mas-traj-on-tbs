范畴论驱动实验系统的工程落地计划与审查包
执行摘要
截至 2026 年 9 月 10 日，我对这个方向的判断是：

不建议把目标定义为“在 TypeScript 里实现一套通用范畴论库”，而应实现一个非常窄的、面向科学实验的 categorical semantic kernel：以 typed open hypergraph 作为规范 IR，以 symmetric monoidal composition 作为组合语义，以受限 DPO rewriting 作为研究扩展机制，再通过结构保持的 lowering 把它编译到现有执行系统。

这个选择有充分的理论和工程依据。对称幺半范畴（SMC）已经为“对象是接口、态射是过程、串接和并行是一等组合操作”提供成熟语义；string diagram 是其对应的图形语言。Structured cospan/open-system 理论进一步证明了“有输入输出边界的系统作为 morphism，由边界进行组合”是一套严格数学结构。

在工程实现方面，Catlab 已经能够以 wiring diagram/C-Set 表示 SMC morphism，AlgebraicRewriting 已实现 DPO、SPO、SqPO、application conditions 等代数图重写，DisCoPy 已提供 string diagram、composition、rewriting 和 functor API，Rust 的 open-hypergraphs 则展示了更偏高性能的数据并行 open-hypergraph 表示。与此同时，这些项目仍明显属于“研究软件/数学基础设施”：Catlab 官方称 applied category theory 和 Catlab 本身仍处于持续研究开发中；AlgebraicRewriting 明确警告 API/行为尚不能假定稳定；open-hypergraphs 的一部分 API 仍标为 experimental。

所以目前真正缺失的是这一层：

[ \boxed{ \text{categorical semantics} \longrightarrow \text{research IR} \longrightarrow \text{typed graph rewrite} \longrightarrow \text{production execution} \longrightarrow \text{scientific provenance} } ]

这恰好可以成为我们系统的核心贡献。

我还检查了你随附的 AdaPDC 源码审查包 72f4b8f。这很重要，因为它意味着这里并不是绿地设计。当前系统已经拥有：

TypeScript DSL；
adapdc.ir/v1；
generator signature 和 type registry；
frozen Plan；
RFC 8785 风格 canonicalization；
SHA-256 CAS；
spec/run/artifact 身份分离；
PostgreSQL catalog；
Temporal worker；
Python implementation artifact；
output path confinement；
sweep 的高层结构保留；
reproducibility snapshot。
因此，我的建议不是推倒重建，而是：

[ \boxed{ \text{AdaPDC v1 execution-oriented DAG} ;\longrightarrow; \text{AdaPDC v2 relation-oriented Research IR} } ]

其中 现有执行、CAS、catalog、frozen artifact 基础设施大部分保留，真正重构的是语义层和 graph/rewrite 层。

最关键的工程决定有六个：

决策	建议
基础语义	typed symmetric monoidal category，而不是 OOP Experiment hierarchy
IR	immutable typed open directed hypergraph，wire 与 boundary 一等公民
copy/delete	绝不能默认 Frobenius/copy semantics；按资源类型区分 copyable / affine / linear
rewrite	MVP 只实现受限 monic DPO + application conditions；SPO 延后
executor	当前 Temporal 保持第一执行后端；Nextflow/CWL/Dagster 是 adapter/export target，不进入语义内核
provenance	分为 intensional research provenance 和 extensional runtime provenance；后者映射 W3C PROV，并导出 RO-Crate/WRROC

特别要强调第三点。Hypergraph category 通常为每个对象赋予 special commutative Frobenius monoid，因此拥有 copy/merge 等结构。
 但 Catlab 官方文档自己也专门提醒：并非所有 SMC 都允许复制和丢弃——制造业资源不能凭空复制，化学物种也不能随意丢弃。

这对 autonomous science 极其重要：

[ \texttt{Dataset}\quad\text{可以共享引用} ]

并不意味着：

[ \texttt{PhysicalSample}\quad\text{也可以被图上 fork 两次}. ]

所以我不会把“hypergraph category”整个照搬进产品，而是用 open hypergraph 做 IR 表示，用 SMC 做最小语义，再显式控制 contraction/weakening 权限。

如果这套设计成功，最终系统里甚至不需要一个重量级 Experiment 类：

[ \boxed{ \text{Experiment}
\text{a versioned typed open diagram} } ]

而 autonomous scientist 的基本动作也不是：

ts
Copy
new Experiment(...)
而是：

ts
Copy
proposeRewrite(baseSnapshot, rule, match)
即：

[ G_t \xRightarrow{\rho} G_{t+1}. ]

这才真正把我们此前讨论的“relation-first”落实到工程约束，而不是换一套 category-theory 名词继续写广义 OOP。

理论基线与必须冻结的工程语义
从对称幺半范畴开始，而不是从 hypergraph category 开始
SMC 给我们的 primitive 足够少：

[ \mathrm{id}_A:A\rightarrow A ]

[ f:A\rightarrow B,\quad g:B\rightarrow C \quad\Rightarrow\quad g\circ f:A\rightarrow C ]

以及：

[ f:A\rightarrow B,\quad g:C\rightarrow D \quad\Rightarrow\quad f\otimes g:A\otimes C\rightarrow B\otimes D ]

再加 symmetry：

[ \sigma_{A,B}:A\otimes B\rightarrow B\otimes A. ]

这套结构正适合“科学转换”：objects 是数据、证据、模型、样品、仪器状态等 typed boundary，morphisms 是 train、measure、transform、evaluate、filter、aggregate 等科学操作。Catlab 的 SMC 文档也直接将 objects 解释为 data/things、morphisms 解释为 processes，并将大型表达式转换成 port-graph 型 wiring diagram。

string diagram 对我们最有价值的地方并不只是可视化，而是：

程序结构本身就是 connectivity，而不是对象内部藏着的 dependency chain。

Selinger 的经典综述系统整理了 monoidal categories 与 string diagrams 之间的图形语言对应关系。

因此第一条 semantic ADR 应直接写：

Experiment 不是 primitive semantic entity。系统的 primitive 是 Type、Generator、Wire、Boundary 与 Composition。

Open system 给“单元实验”一个比 object 更合适的定义
Structured cospan 的关键思想是让开放系统拥有明确 boundary：

[ L(A)\rightarrow X\leftarrow L(B) ]

并将这样的开放系统作为 morphism 组合。Baez、Courser 等人的结果表明，在适当有限余极限条件下，可以由 structured cospans 得到 symmetric monoidal category / double category。

映射到我们的系统：

[ \boxed{ \text{ResearchUnit}
(\text{input boundary}) \to (\text{internal graph}) \to (\text{output boundary}) } ]

于是“卡片”也不再需要是 object，而可以只是对一个 open diagram 的命名视图：

text
Copy
card = label + docs + ref(openDiagramDigest)
这也意味着文件目录结构退回为 storage concern，而不再负责表达研究结构。

Open typed hypergraph 是 IR，而不是数学语义本身
这一区分非常重要。

我建议：

[ \text{semantic theory}=\text{typed SMC} ]

而：

[ \text{canonical representation}=\text{typed open directed hypergraph}. ]

Rust open-hypergraphs 项目已经展示了类似方向：显式 global sources/targets、hyperedges、adjacency，并实现 composition、tensor、functor 等算法，同时支持 JSON serialization；但其部分 API 截至目前仍标为 experimental，因此更适合作为 representation/performance 参考，而不是我们 TypeScript 产品的直接 runtime dependency。

Catlab 采取了类似的“公式语法 → combinatorial port graph”路线：官方文档明确指出大型 SMC term 用树表示过于冗长，因此转而使用 DirectedWiringDiagrams，底层可进一步表示为 attributed C-Sets。

这为我们的设计提供了很明确的经验：

TS DSL 可以像程序，IR 不应该像 AST tree，而应该像 normalized connectivity structure。

copy、discard、merge 必须进入资源类型系统
这里我认为应该比绝大多数 workflow 系统更严格。

建议 wire type 不是单纯：

ts
Copy
Dataset
而是：

ts
Copy
{
  valueSchema: DatasetSchema,
  mode: "copyable"
}
最小资源 modality：

[ \boxed{ \texttt{copyable},\quad \texttt{affine},\quad \texttt{linear} } ]

语义大致为：

mode	可复用	可丢弃	典型科学对象
copyable	是	是	immutable dataset、configuration、model artifact
affine	否	是	一次性 capability、临时 reservation
linear	否	默认否	physical sample、试剂份额、某些设备状态 token

这不是为了“炫 linear logic”，而是为了阻止自主 agent 产生物理上不合法的研究图。

Catlab 自身就在 wiring diagram 文档中指出，SMC 并不天然允许 copy/delete；例如 manufacturing resource 不能复制、chemistry species 不能任意 discard。

因此：

text
Copy
Dataset ─┬─> train A
         └─> train B
可以通过显式或可推导的 copy 合法化，而：

text
Copy
Sample42 ─┬─> destructive assay A
          └─> destructive assay B
应在构图/重写阶段就失败，而不是等执行器发现样品没有了。

DPO 是默认 rewrite，不应一开始同时暴露所有 rewrite calculus
经典 algebraic graph transformation 已经形成完整体系，包括 typed graphs、attributed graphs、DPO/SPO、application conditions、confluence 等。
 Adhesive category 理论的核心意义之一，就是使沿 monomorphism 的 pushout 行为良好，并使 DPO graph rewriting 能推广到广泛 graphical structures。
 近年的 Isabelle/HOL 工作还对 DPO 的基础定义、pushout/pullback、derivation uniqueness 和 Church-Rosser 结果进行了机器形式化。

工程上我建议规则固定为：

[ L \xleftarrow{l} K \xrightarrow{r} R ]

其中：

(L)：必须匹配的旧结构；
(K)：必须保存的 interface；
(R)：替换后的结构。
AlgebraicRewriting 的官方 demo 就是以 L ← I → R 构造 DPO rules，并检查 dangling condition；同一个库还能切换 SPO、SqPO，并支持 positive/negative application conditions。

为什么 MVP 选 DPO：

删除必须显式安全。

比如 agent 想把：

text
Copy
A -> B -> C
     |
     +-> D
中的 B 删掉。

如果它没有同时说明如何处理外部连接 D，DPO dangling condition 应阻止该 rewrite。这种“不允许悄悄删掉上下文”的保守性特别适合 autonomous science。

SPO 可以后续增加，用于我们明确希望“删除元素时自动处理相关连接”的场景，但不能让 agent 任意选择 rewrite semantics。

Categorical DB 是 integration algebra，不应该成为 MVP operational database
Functorial data model 把 database schema 表示为 finitely presented category，把 schema 上的 instance 表示为 Set-valued functor；schema functor (F:S\to T) 会诱导 (\Delta_F,\Sigma_F,\Pi_F) 三种数据迁移 functors。
 这已经被实际用于 computational science 的异构材料数据库整合，CQL 相关工作展示了对 Open Quantum Materials Database 等数据源进行 structure-preserving integration。

这对未来的：

text
Copy
external dataset schema
       ↓
research schema
       ↓
experiment result schema
非常有价值。

但它不意味着 PostgreSQL 要被 CQL 替掉。

我的边界是：

[ \boxed{ \text{categorical DB}
\text{schema integration / migration layer} } ]

而：

[ \boxed{ \text{PostgreSQL}
\text{operational catalog/index} } ]

这是控制 scope 的重要措施。

ts

元素身份必须与数组位置脱钩
DPO 最大的工程坑之一会是：

rewrite 后 vertex/edge index 全变了，provenance 如何跟？

我的规则是：

K 中被保留的元素保持 identity。

新元素 identity 则确定性生成：

[ ID_{\mathrm{new}}
H( baseDigest, ruleDigest, matchDigest, localRuleName ) ]

因此同一个：

text
Copy
base snapshot
+ rule
+ match
+ params
应产生同一个 rewritten snapshot。

数组位置只用于 serialization。

这也避免要求 hot path 求一般 graph isomorphism。

composition 应是一等 API

最终 Go / No-Go 标准
我认为最后不应该问：

“我们是不是成功用范畴论写了一个实验框架？”

而应该问四个非常现实的问题。

第一，研究变化是否变得局部？

旧方式可能是：

text
Copy
copy directory
change config
edit script
patch evaluator
update naming
remember provenance
新方式应该是：

[ G\xRightarrow{\rho}G'. ]

如果 parameter sweep、ablation、hypothesis refinement 仍然需要大量外围特殊代码，那么 relation-first 假设并没有被验证。

第二，错误是否更早暴露？

我们真正希望看到：

text
Copy
illegal resource duplication
incompatible ablation
dangling deletion
wrong metric/data connection
stale rewrite
在运行前失败。

若 categorical layer 只让代码更复杂，而没有排除新的错误类别，应当停止扩张。

第三，execution backend 是否真的可以替换？

现在至少应证明：

[ F_{\mathrm{Temporal}}:\mathcal R\to\mathcal P_T ]

是独立 lowering。

后续再试：

[ F_{\mathrm{CWL}},\qquad F_{\mathrm{Nextflow}}. ]

CWL 的明确输入输出和任务隔离、Nextflow 的 dataflow/HPC/cloud 能力，使两者都适合作为这一验证的第二阶段 target。

如果为了 Nextflow 必须修改核心 Research IR，那说明分层失败。

第四，也是最重要的：Agent 的搜索空间是否因此变得更好？

AI Scientist-v2 证明了 tree-search 式 autonomous experimentation 可以工作。
 我们真正需要证明的不是“agent 也能操作 hypergraph”，而是：

[ \boxed{ \text{typed rewrite space} < \text{arbitrary code-editing space} } ]

这里的“小于”指的是：

非法实验更少；
可复用研究动作更多；
provenance 天然完整；
分支可回放；
agent 不必读整个仓库；
experiment family 不需要复制目录；
search state 可以直接 hash；
相同研究转换可以跨项目复用。
如果三种科研验证最终显示：

[ \text{sweep}, \quad \text{ablation}, \quad \text{hypothesis refinement} ]

都可以被压缩成：

[ \boxed{ \text{small typed rewrite rules} } ]

并且新的研究场景主要通过新增 generator/schema/rule，而无需持续扩大 kernel，那么这个架构才应该进入下一阶段。

反之，如果每增加一种 scientific reasoning 就要修改：

text
Copy
IR core
rewrite engine
executor
catalog
agent API
那我们实际上只是把：

[ \text{OOE God Object} ]

变成了：

[ \text{Categorical God Framework}. ]

这应该是整个审查包里最重要的否决条件。

综合理论、现有实现以及你当前 AdaPDC 72f4b8f 的工程基础，我给出的具体路线因此不是“重新实现整个系统”，而是：

[ \boxed{ \begin{aligned} &\text{保留：CAS + frozen signatures + catalog + Temporal + worker}\ &\text{重构：node-centric IR}\rightarrow\text{open relation IR}\ &\text{新增：resource modality + DPO rewrite + research provenance}\ &\text{验证：三种真实 scientific rewrite}\ &\text{对照：Catlab + AlgebraicRewriting + DisCoPy}\ &\text{互操作：PROV + RO-Crate + 后续 CWL/Nextflow}\ &\text{约束：agent 只能 propose rewrite，不直接 mutate/execute} \end{aligned} } ]

我认为这是截至目前最现实的范畴论工程化切入点：不追求“把整个科研系统范畴化”，而是在最值得形式化的那一层——实验的组合、边界、资源使用、局部变换和推导历史——建立一个足够小、足够严格、能够被 autonomous agent 安全操作的 Research IR。
