## 2. 四个阶段的实体内容(10 条长消息,合计 47,240 字符)

**阶段一 · 前沿梳理(第 1 轮,6,446 字符)**:主线是「优化提示词 → 优化运行代码 → 优化需要完整证据 → 改动须过回归验证」。点名 ACE(2510.04618)、AutoHarness(2603.03329)、Meta-Harness(2603.28052,**保留可追溯的优化历史**,五个未参与优化的模型上平均 +4.7pp)、Self-Harness(2606.09498 v3);再是插件/预算/实例适配四篇:PluginRSI(2609.32423,插件分 roles/tools/skills/memory;**种子库已有 75 个插件**)、MESH-Harness(2610.05300,槽位 + LinUCB + 多起点坐标上升;相比 Meta-Harness **+2.00–7.01pp、总成本低 14.6%**)、Turbo Harness(2609.40330,全局 harness → 按实例出补丁)、Raven(2609.33439,模型+harness 成组合单元)。
**反面证据**(对话特意与正向成果并列):「强模型未必需要复杂编排」(2609.40303)、「哪种组件有用取决于任务」(2609.32459)、「自改进可能制造不存在的问题」Phantom Guardrails(2607.13083,虚构失败 **15/60** vs 对照 **0/60**)、「得分提高可能只是修复了评估缺陷」(2610.05533)。

**阶段二 · 三方联合优化(第 2 轮,4,671 字符)**:MCPP(2605.06110,`max Pr(成功 且 T≤D 且 C≤B)`,Monte Carlo Portfolio Planning)、**EvoRoute**(2601.02695,逐步模型路由;delay 明确定义为 total wall-clock;一组汇总 74.27%→74.60% / $521.61→$138.40 / 123.00→92.23h)、cua-speedrun(2609.40284,受控计时方法最值得迁移)、MoFlow(2609.38294,**降一级**:用 token 数与串行轮数替代真实费用与墙钟)、DolphinBench(2609.24971,三角色 600 任务,**把前置构建成本计入**),另加 Latency/Token-Aware TTC(2509.09864)与 AI Agents That Matter(2407.01502)。

**阶段三 · 多模型猜想的证据边界(第 3–6 轮,这是全篇最要紧的部分)**

- 第 3 轮(4,539 字符)结论:**还不够**,并补了五个方向 —— ①执行编译与工具合并(LLMCompiler 2312.04511;Meta-tools 2601.22037,−11.9% 模型调用 / +4.2pp)、②协程式代码执行(Policy as Code 2609.29251)、③推测执行(Speculative Actions 2510.04371、TomasuLLM 2609.38201,1.27–1.35×)、④上下文管理基线(observation masking 2508.21433)、⑤验证频率与检查点(2610.02488,Young–Daly 式检查点,只核了摘要未审假设)。另给出:把"模型无关/任务无关"拆成**四格可检验要求**(接口/模型迁移/任务迁移/优化收益);**建议架构 = 通用执行器 + 可校准控制器**,动作集 `{继续、批处理、并行、取回上下文、验证、重试、停止}`;以及**四×二泛化测试矩阵**(已见/未见模型 × 已见/未见任务,各分冻结策略与固定小预算校准)。
  ⇒ 该动作集与已入库长程评测报告里的 OCP 动作集**几乎同构**,是重复出现,不是新提法。
- 第 4 轮(4,604 字符)结论(**全篇最重要的一句**):**只能支持"有条件的优势",不能支持"多模型/多供应商在多数情况下三维都更优"。** 内含:
  - 三个维度必须分开:多 agent / 多模型 / 多供应商("多供应商"的价值可能只是容量、价格、可用性、延迟)。
  - **一个可证但很弱的命题**:若 `Π₁ ⊆ Π₊` 且不强加开销,则 `V_{Π₊}(B,D) ≥ V_{Π₁}(B,D)` —— 即"多模型**可选**不劣",但"实际使用多模型"无无条件保证。
  - **更强的条件优势**:A Unified Approach to Routing and Cascading(2410.10347,ETH)——**质量估计能力**决定路由/级联能否有效;并自推收益空间 `G = E[max_m u_m] − max_m E[u_m] ≥ 0`,现实中要扣掉选择误差损失、执行额外开销、摊销学习成本。
  - **实证两面**:FrugalGPT(2305.05176)、RouteLLM(2406.18665)、EvoRoute 支持;而 **Self-MoA(2502.00674)是直接反例** —— 同一强模型多次生成再聚合可胜过混合不同模型,故"单模型"≠"单次采样",对照必须包含同模型多试,否则会把"多花算力"的收益误记为"异构"的收益。
  - **最贴近本猜想的新工作**:Resample or Reroute?(2607.08665)—— 直接比较"继续采样当前模型 vs 转向另一模型",**收益在异质性更强的基准上较大,并随验证器质量下降而缩小**(回放证据,未解墙钟目标);FlexRouter(2609.38585)。
- 第 5 轮:既然允许多模型,**路由与判断路由的成本就是 harness 的内生决策**。第 6 轮:已有**部分结论**,方向并非无证据。

**阶段四 · 四篇精读(第 7–10 轮)**

- **2610.01618《Agents Are Systems, Not Models》**(第 7 轮):四项科学任务、单主控 + 专业模型资源。最要紧的四点:提供有效操作信息可同时提高得分并降低运行时间与估算成本;信息因素的重要性**随模型变化**;**天文学问答里 99.8% 的运行使用了较弱的专业模型,平均 68.5% 而主控直接回答 96.7%** ⇒ **增加可用模型不保证系统会正确选择**;oracle 验证提高质量但也增加时间与成本。口径限制:成本主要按 token 与标价估算(非完整实际成本),部分分析只覆盖完成的运行。三条推论:多模型**可用**≠多模型**获益**;须把"信息优势"与"模型组合优势"分开(再交叉设置一条轴);"模型无关"应指**接口与控制机制可迁移**。它建议主评估改为 **`S_π(t,c) = Pr(通过 ∧ T_端到端 ≤ t ∧ C_完整 ≤ c)`**(双预算内的成功概率)。
- **EvoRoute 精读**(第 8 轮,9,188 字符,最长):定位为"**值得复现的研究原型**"。**`bingreeky/evo-route` 仓库 404**(我复核:确为 404,但不能断定已删除);它是 step-level 路由,**静态配置 ≠ 单模型**;多目标应按 **Pareto 解**理解;"Agent System Trilemma"是其命名,**不是**不可能性定理。
- **作者其它仓库**(第 9 轮,4,704 字符):五个都真实存在(我复核 ★ 数见 §3)。**最有价值的发现是 MemEvolve** —— `_pareto_select_top()`(:623)对 (accuracy↑, total_tokens↓, execution_time↓) 做**非支配排序**,同层用 **0.6/0.25/0.15** 加权;接口 `BaseMemoryProvider` 只有初始化/提供记忆/吸收轨迹三个方法。⇒ **"对 agent 外部机制做成功率—资源—时间三目标优化"已有工程先例,不能再当空白。** 边界(我复核):`use_pareto_selection=False` **是默认值**;成本用总 token(不能跨供应商比);时间取自日志 `metrics.elapsed_time` 且缺失时返回 `0.0`(缺日志的候选可能被误判为最快)。
- **MemEvolve + EloScaling**(第 10 轮,7,703 字符):给出 EloScaling 的推导 `r_n − r_m = 400·log₁₀(n/m)`(由 `Pr(M_n>M_m)=n/(n+m)` 与 Elo 变换),并列出**四条缺口**说明它不足以当停止规则(会话状态价值不同、交叉点不等于有限预算全局最优、二元通过率会饱和、最优候选未必可识别可交付);另点出两个复现坑(`export_selfelo_ci.py` 会给提前结束的会话延续最后成绩;公开 CLI 适配器 `cost_usd` 为 `None`)。最后给出**四路对照**(单模型单会话 / 同模型多会话 / 多模型多会话 / 多模型动态切换,每项都要匹配总费用与墙钟)**与一阶随机支配推导**:`F_A(y|b) ≤ F_B(y|b) ∀y` 时把 A 换成 B 不改善最大值分布 ⇒ **多样性本身不足以保证收益**。
- 第 10 轮还列了三篇"判别"相关引文:OpenDeepThink(2605.15177,成对比较 + Bradley–Terry)、Scaling Test-time Compute for LLM Agents(2506.12928)、EdgeBench(2607.05155)。
