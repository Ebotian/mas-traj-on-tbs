**Agent Engineering Science：截至 2026-09-24 的进展与可复用实现**

基于用户提供的 agent_engineering_science_repro_bundle(1).zip，并核查相关论文、作者项目和 GitHub 实现。

本文的中心判断是：Agent engineering science 已进入“实验工具链可用、局部经验规律正在形成”的阶段。预算感知、上下文操作、执行反馈优化和多维可靠性评测已经有具体方法与实证；跨任务的统一缩放定律、决策充分状态、长期知识闭环稳定性和开放式研究中的在线价值估计仍未解决。这里的成熟度判断是本次综合分析，不是某个社区统一评级。

本次工作读取了附件中的报告、24 条参考文献及三份 CSV；检索了论文版本，阅读了相关仓库 README，并针对预算控制、答案选择、上下文折叠、时间记忆和优化器接口检查了实现片段。没有运行付费 LLM benchmark，没有独立复现各论文性能，也没有对所有仓库作完整代码审计。文中的“论文报告”“源码确认”“本文推论”分别表示不同证据。

**研究对象应当是整个闭环。** 附件将 agent 定义为部分可观测、资源受限、能够修改自身信息和计算结构的随机系统，这个方向成立。实际需要辨识的对象可以写成：

$$
Y=f(M,H,E,V,D,B,\omega),
$$

其中 \(M\) 是模型，\(H\) 是执行与编排机制（harness），\(E\) 是环境和工具，\(V\) 是评价器，\(D\) 是任务分布，\(B\) 是预算，\(\omega\) 是随机性。应当报告的 \(Y\) 至少包括任务质量、资源成本、重复执行可靠性和失败严重程度。

模型能力、编排效果、环境便利程度、评分器偏差都会改变最终分数。若目标是评价整个产品，编排机制本来就是研究对象；若目标是评价模型，编排必须控制或显式分层。这两个目标需要不同的实验设计。

| 研究方向     | 当前已出现的进展                                 | 仍然缺少什么                | 本文判断            |
| -------- | ---------------------------------------- | --------------------- | --------------- |
| 计算与行动预算  | BATS、agent test-time scaling 将工具和推理成本显式化 | 跨任务迁移的在线价值估计与最优停止     | 已有可用方法和局部实证     |
| 协作与信息拓扑  | 受控比较单 agent、中心化、去中心化、独立和混合结构             | 跨环境有效的架构选择规律及独立证据度量   | 经验规律形成中         |
| 上下文与观测   | ReSum、AgentFold、RLM 将压缩、选择和分解变成操作        | 可检验的决策充分性、压缩后纠错能力     | 实现发展快，理论未闭合     |
| 自动优化     | GEPA、ACE、ADAS、DGM 把提示、经验或程序变成搜索对象        | 评价器有效性、迁移、长期退化和自我强化偏差 | 有效但高度依赖反馈       |
| 记忆与知识状态  | Graphiti 等实现时间有效性和来源追踪                   | 证据独立性、资格判定、撤销传播       | 数据结构较成熟，认识论控制薄弱 |
| 可靠性与失败分析 | 多维指标、扰动、工具故障、MAST 失败分类                   | 多日会话、恢复、不可逆副作用和环境漂移   | 评测方法开始体系化       |
| 步骤归因与训练  | TRACE、HCAPO、GDCR/SAPO 提供更细粒度信用分配         | 无标准答案时的在线研究价值         | 训练侧进展明显         |

| 工程计量     | Inspect、Harbor、OpenTelemetry、PROV、OCEL   | 跨框架统一语义和“为什么相信”的状态记录  | 底层可复用，研究层需定制    |

这些方向构成一个有关联的研究面，但目前不能据此声称已经存在统一、公认的“Agent 工程科学理论”。

**最值得补入原报告的，是有条件的系统缩放规律。** [Towards a Science of Scaling Agent Systems](https://arxiv.org/abs/2512.08296v3) 的 2026-04-08 版本研究 260 个配置、6 个 benchmark、5 种架构和 3 个模型家族。其跨验证 \(R^2\) 为 0.373；换用任务相关能力指标后为 0.413。相对单 agent 的变化从可分解金融推理上的 +80.8%，到顺序规划上的 −70.0%。这些都是作者实验范围内的相对变化，不能写成百分点。

这项工作的价值是把“是否协作”变成架构与任务结构的匹配问题：可分解性、通信开销、工具负担和单体能力会共同改变收益。它并不支持“多 agent 总是更好”，也不支持“单 agent 总是更好”。

需要同时保存版本和适用范围：早期版本常被转述的 180 个配置、\(R^2=0.513\)，与当前 v3 不同；“87%”是留出配置上的架构识别表现，不能解释为对任意真实任务有 87% 选型成功率。作者仓库的 [DATA_AVAILABILITY.md](https://github.com/ybkim95/agent-scaling/blob/main/DATA_AVAILABILITY.md) 表明，SWE-bench Verified 和 Terminal-Bench 各只用了 20 个任务。因此它是很有价值的中层经验模型，距离普适工程定律仍有明显距离。

[代码及复现指南](https://github.com/ybkim95/agent-scaling) 已提供五种架构、Hydra 配置和实验输出规范；README 指定复现版本 v2.1.3。其对 Nature Machine Intelligence 的描述是仍在修订审稿，不应据此写成已被该刊接收。原报告中 GPTSwarm、ADAS 是架构可优化化的先驱；这项工作补上了系统性比较与边界辨识。

**预算分配已经从“增加 token”推进到“让策略知道资源约束”。** 原附件的 CATS 引用需要更新。Google 的旧链接现在使用标题 [Budget-Aware Tool Use Enables Effective Agent Scaling](https://arxiv.org/abs/2511.17006v2)，2026-08-17 的 v2 和当前公开仓库使用 Budget Tracker / BATS 名称，第一作者为 Tengxiao Liu。

[google-research/budget-aware-agent](https://github.com/google-research/budget-aware-agent) 提供三个可对照实现：ReAct 基线、加入预算信息的版本，以及加入规划和自验证的 BATS。检查 src/agent_budget_tracker.py 可见，预算信息会持续写入上下文，搜索和浏览调用也有实际截断。这里需要区分两种机制：控制器执行硬预算，模型利用剩余预算改变策略。只有前者不能保证资源利用有效，只有后者不能保证不超支。

这对“以行动作为思考过程”的直接启发是：检索、运行实验、分支探索、验证、压缩状态都可以作为有成本的计算动作。研究目标应是质量—成本前沿，以及什么时候选择哪种动作；行动链更长本身不能成为质量指标。[2025 年的系统研究](https://arxiv.org/abs/2506.12928) 已分别比较并行采样、顺序修订、验证、合并和轨迹多样化。

源码还提供一个计量上的提醒。BATS 的 src/select_answer.py 将“存在正确候选的比例”和“选择器实际选对的比例”分开，这是值得借鉴的；但离线脚本会利用标准答案评分，在候选全部正确或全部错误时跳过选择调用。在评分标签正确、选择器被保证从候选中选一个的条件下，这种捷径不改变二元正确率；若测部署时延和选择器成本，则必须计入真实部署所需调用。不能直接把该离线短路后的运行成本当成线上成本。

**上下文已经成为 agent 可以操作的状态接口。** 这里有三条不同路线，不能都归为“摘要”。

| 方法                                            | 主要改变                           | 重要边界                     |
| --------------------------------------------- | ------------------------------ | ------------------------ |
| [ReSum](https://arxiv.org/abs/2509.13313v3)   | 周期性把历史变成继续执行所需的摘要；也研究专门训练      | 训练无关版本与 ReSum-GRPO 应分开比较 |
| [AgentFold](https://arxiv.org/abs/2510.24699) | 模型主动选择折叠的历史范围与粒度               | 论文成绩包含模型训练贡献             |
| [RLM](https://arxiv.org/abs/2512.24601v3)     | 把长输入放在外部执行环境中，通过程序访问、分解和递归调用处理 | 输入长度扩展不等于长期记忆正确或任意任务可靠   |

在 Alibaba 的 [AgentFold/infer.py](https://github.com/Alibaba-NLP/DeepResearch/blob/main/WebAgent/AgentFold/infer.py) 中，compression range、compressed text 和历史 step 更新是实际执行接口。RLM 的[作者实现](https://github.com/alexzhang13/rlm)则把上下文作为 REPL 中的变量，允许子调用。两者都说明信息访问方式已经成为可实验的设计变量。

但保留文本含义与保留未来决策能力并非同一件事。一个摘要可能足以延续成功路径，却删掉恢复失败所需的命令、版本或反例。实验除了最终得分，还应测压缩后回查、纠错和分支切换。RLM 论文也明确提到子调用成本膨胀等局限；不能用“可处理更长输入”替代成本和可靠性验证。

**自动改进已经有可复用优化器；评价器仍决定改进方向。** [GEPA](https://arxiv.org/abs/2507.19457v2) 将执行轨迹、错误和反馈转成反思式修改，并维护表现互补的候选。其 [GitHub 实现](https://github.com/gepa-ai/gepa) 已可优化多种文本参数；src/gepa/core/adapter.py 把任务执行、评分、轨迹和反思数据接口分离。这使它较适合接入既有 agent，而无需将整个系统迁入另一套编排框架。

[ACE](https://arxiv.org/abs/2510.04618v3) 则将经验维护成可累积、可局部修改的 playbook。[作者仓库](https://github.com/ace-agent/ace) 的设计包含增量更新、helpful/harmful 计数和整理过程，主要对抗反复全文重写导致的信息丢失。GEPA 偏重候选搜索与选择，ACE 偏重跨任务经验更新；两者可以研究组合，但不能预设组合必然有收益。

更广的研究脉络包括 [ADAS](https://arxiv.org/abs/2408.08435) 的程序化 agent 搜索、[GPTSwarm](https://proceedings.mlr.press/v235/zhuge24a.html) 的图结构与节点优化，以及 [DGM](https://arxiv.org/abs/2505.22954) 的自修改探索。它们证明自动设计空间是可操作的，不意味着开放式自改进已经有收敛或正确性保证。

对这些方法，至少要冻结独立测试集、保留候选谱系、区分执行失败与科学负结果，并记录优化器实际调用评价器的总成本。GEPA 的 Pareto 候选机制也不自动等价于用户要求的多目标优先级；若项目规定“主指标优先，副指标仅在主指标允许的范围内比较”，必须在适配器和晋升规则中明确实现。

**可靠性评测比原报告列出的 ReliabilityBench 更广。** [Towards a Science of AI Agent Reliability](https://arxiv.org/abs/2602.16666v3) 在 2026-06-02 的 v3 中比较 15 个模型、2 个 benchmark，使用 12 个指标覆盖一致性、鲁棒性、可预测性和失败严重程度。早期摘要的模型数是 14；总结当前进展应使用新版本。

论文观察到，能力提升只带来有限的可靠性提升。它并没有证明所有可靠性维度都没有进步；不同环境与指标表现不同。更有用的工程结论是：任务成功率、重复执行稳定性、置信度校准和失败后果需要分别测量。对于开放式探索，也不应要求每次轨迹完全相同。

[MAST](https://arxiv.org/abs/2503.13657v3) 进一步提供 1600 多条多 agent 轨迹、14 种失败模式和 3 类问题：系统设计、agent 间失配、任务验证。[代码和数据](https://github.com/multi-agent-systems-failure-taxonomy/MAST) 可用于建立失败分类，但该 taxonomy 是诊断词汇，不是因果证明或自动修复器。

[Measuring Agents in Production](https://arxiv.org/abs/2512.04123v4) 提供了对照性的现场证据：20 个深入案例和覆盖 26 个领域的 86 名已部署系统从业者调查中，68% 报告其系统在人介入前最多执行 10 步，70% 主要使用现成模型加提示，74% 主要依靠人工评价。这是特定调查样本的描述，不是全球部署普查；它说明研究中长程自主性的成绩与生产部署实践仍有距离。

Harbor 的旧组织地址会重定向到 harbor-framework/harbor。移植或引用时应使用当前地址并固定版本。AstaBench 当前 README 提供超过 2400 个样例、11 个 benchmark；其任务同时覆盖文献、代码、数据分析和端到端研究。它还保留任务提供工具的时间和语料限制，这对防止后来的知识改变历史任务评分有实际意义。

[W3C PROV](https://www.w3.org/TR/prov-primer/) 可以表达产物、活动、主体之间的来源关系；[OCEL 2.0](https://www.ocel-standard.org/) 可以表达多对象事件关系。两者适合复用，均不自动回答“这个 claim 是否值得信任”。

[Graphiti](https://github.com/getzep/graphiti) 的 graphiti_core/edges.py 已有 episodes、valid_at、invalid_at、expired_at、reference_time 等字段。这是时间事实与来源追踪的具体实现，但这些字段也可能由错误抽取产生。多篇来源来自同一上游、同一模型重复表述、过期结论被压缩后重新引入，都需要额外的资格与暴露关系。本文建议保留来源依赖、适用条件、撤销原因、反例和晋升规则；这是对既有工程能力的扩展建议。

**步骤归因的研究进步必须按信息条件解释。**

| 方法                                                    | 归因方式                                         | 不能直接迁移的条件                      |
| ----------------------------------------------------- | -------------------------------------------- | ------------------------------ |
| [TRACE，2026-07](https://arxiv.org/abs/2607.13988)     | 工具调用边界上，以冻结参考模型的标准答案 log-prob 构造状态值，再取 TD 差分 | 训练奖励需要标准答案信息；普通黑盒 API 未必提供所需概率 |
| [HCAPO，2026-03](https://arxiv.org/abs/2603.08754)     | 利用事后 hindsight critic 改善步骤价值与 advantage      | 事后归因不等于行动前可获得的可靠预测             |
| [GDCR/SAPO，2026-05](https://arxiv.org/abs/2605.29697) | 利用训练期实体关系图上到答案节点的距离给步骤信用                     | 未知答案的开放研究中不能直接计算同样的距离          |

这些是 agent 训练中的进展。对于只能调用现成模型 API 的 agent 插件，更容易吸收的是其轨迹分段、状态转移记录和实验诊断思想。将论文中的离线奖励直接替换成模型“觉得自己进步了”的分数，会改变方法所依赖的信息条件。

世界模型也面临相同问题。[Current Agents Fail to Leverage World Model as Tool for Foresight](https://arxiv.org/abs/2601.03905v2) 在所测视觉及 agent 任务中观察到模拟工具调用不足、预测误用和部分性能下降。它支持研究“何时模拟、如何整合预测”，并不支持所有世界模型无效这一更强结论。

**科学 agent 已经是有用的压力测试环境。** [AI Scientist-v2](https://github.com/SakanaAI/AI-Scientist-v2) 将假设、实验、分析和论文组织成探索流程，并使用渐进式树搜索。但仓库主动说明：相较已有强模板的 v1，v2 并不必然产出更好的论文，探索更开放时成功率可能更低。这提示我们，应分别评估任务开放程度、实验正确性、发现价值和最终文本质量。

**理论框架下一步需要收紧五个定义。** 以下是本文的数学分析，不是既有论文已经验证的结论。

1. 决策等价必须区分当前动作与未来控制。两个历史当前最优动作相同，并不保证下一轮信息价值、恢复路径和最优动作仍相同。对多步任务，需要接近受控 Markov 充分性的条件，或直接检验抽象状态下的未来价值误差。可以把目标写成预算约束下的决策损失：

   $$
   \mathcal R(\Phi,\pi)=
   \mathbb E_H\left[\max_a Q(H,a)-Q(H,\pi(\Phi(H)))\right].
   $$

   这个指标需要可计算的 \(Q\) 或明确的代理任务，不能假装真实开放研究中的 \(Q\) 已知。

2. \(I(H;Q(A))-I(S;Q(A))\) 需要先定义随机变量和任务分布。互信息并不会自动成为可估计的工程量。实践中更适合先在封闭环境测错失关键事实后的行动损失，再研究信息论近似。

3. \(\arg\max \mathbb E[\Delta V]/\mathbb E[C]\) 是可能有用的短视分配启发式，不是一般最优解。若两个昂贵信息动作存在互补，逐次贪心比值会错过它们。把 deterministic 计算成本 \(c\) 放入有限预算的元决策问题，可写：

   $$
   V(b,B)=\max\left\{
   V_{\rm stop}(b),\
   \max_{c\le B}\left[-\lambda c+\mathbb E V(b',B-c)\right]
   \right\}.
   $$

   这里 \(b\) 是信息状态，\(\lambda\) 将成本转换成效用惩罚。真正的困难是估计转移和值，而不是写出方程。

4. \(N_{\rm eff}=N/[1+(N-1)\rho]\) 来自等方差、等相关样本均值的方差匹配。它不单独决定多数投票的尾概率，更不等于独立证据数量；相同二阶相关结构仍可能有不同高阶依赖。真实实验应在控制任务难度后估计错误依赖，并显式干预共享上下文与来源。

5. 把“一条错误结论未来被用了多少次”命名为 \(R_e\)，尚不能直接套用 \(R_e<1\) 的繁殖阈值。反复使用旧错误与产生新的、会继续传播的错误后代不同。更合适的起点是区分错误类型、暴露、采纳、复制与纠正，在受控环境辨识局部矩阵 \(J\)：

   $$
   e_{t+1}\approx J e_t+\eta_t.
   $$

   在相应局部、近似平稳条件下研究 \(\rho(J)<1\) 的误差衰减，才是可检验的稳定性假说；这仍不构成整个真实 agent 的全局稳定保证。

**值得优先开展的是三个可证伪问题。**

| 问题            | 对照                      | 主要结果                  | 关键混杂控制         |
| ------------- | ----------------------- | --------------------- | -------------- |
| 预算信息是否改变行动效率？ | 硬上限但不告知、持续告知、告知加自适应切换   | 同预算成功率、同质量成本、超支率      | 同模型、工具、任务和调用计价 |
| 什么状态足以继续与恢复？  | 原始历史、摘要、结构化状态、状态加原始证据回查 | 完成率、纠错率、恢复时间、成本       | 人工注入同一遗漏或过期信息  |
| 共享信息是否造成错误放大？ | 全共享、证据共享、先独立后汇总；有无资格门槛  | 错误采纳、后代错误数、纠正时延、有效成功率 | 控制来源、任务难度与总预算  |

筛选阶段可用 24 个任务、2 个模型、4 个策略、3 次重复，共 576 个 episode；这只是预算设计示例，三次重复不足以单独支撑高可靠性宣称。先用 pilot 估计方差，再决定正式样本量。独立重采样和置信区间应以任务为主要单位，避免把同一任务的多次运行当作完全独立的新任务。

用固定小语料和可重置工具环境完成机制试验，再迁移到真实仓库或算法研究任务。保存原始 artifact、模型/编排/数据/评价器版本、每次实际成本、失败和人为介入；不要只留下“最好的一次”。

这些实验可以产出真正有工程价值的中层规律：在怎样的任务、预算、错误来源和恢复条件下，某种状态、协作或验证策略有用。超出已测范围时，保留“不知道”，比把一种成功案例过早包装成普适架构更有研究价值。
