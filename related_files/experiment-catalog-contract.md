# Experiment Catalog 接口契约（v0.1）

> 状态：**语义契约**，不是数据库 DDL。
> 本版本固定身份、隔离、不可变性与恢复语义；具体表结构与字段经最小闭环验证后再收敛。
> 数据库选型（当前 SQLite + Drizzle，TS 层）见相关工程讨论；本契约不绑定特定 ORM 或驱动。

## 0. 范围与定位

### 0.1 三个模块的职责边界（硬约束）

| 层                | 职责                            | 禁止             |
| ---------------- | ----------------------------- | -------------- |
| **数值内核**（Python） | 接收数组、参数、状态，返回结果               | 不依赖数据库；不负责文件路径 |
| **Python 任务入口**  | 读冻结清单 → 加载数据 → 调内核 → 写结果与产物清单 | 不直接触碰 catalog  |
| **TS catalog**   | 解析身份 → 验证产物 → 登记关系与状态         | 不参与数值计算        |

语言边界（TS/Python）只是落实手段，**职责边界才是关键**：文件读写收敛在任务入口，数据库读写收敛在 catalog，数值内核两者都不碰。

### 0.2 数据库与文件的边界

* 数据库只存**管理信息与摘要**：版本、哈希、位置、运行状态、关系、汇总指标。
* 高频日志、完整轨迹、大对象（数据/模型）**写文件**，目录只记录位置与内容摘要。

---

## 1. 身份与不可变性

三个身份必须区分，不可混用：

| 身份       | 含义             | 关键性质                       |
| -------- | -------------- | -------------------------- |
| **实验规格** | 冻结的版本、配置、数据、种子 | 可版本化、不可变；相同规格可运行多次         |
| **运行尝试** | 某一次实际执行        | 有唯一 run id；一次规格对应 0..n 次运行 |
| **产物**   | 某份确定内容         | 内容寻址；不同运行可共享同一产物           |

**版本 vs 别名**：

* 版本（如 `0.1.0`、数据集内容摘要）**不可变**，一经登记不再改变。
* `latest` 是**可变别名**，指向当前某个版本；解析发生在登记时刻，运行时**不再追随 latest**。

---

## 2. 输入解析

`resolveDatasetVersion` 返回**确定清单**（内容寻址：id + 版本 + sha256），不返回可漂移的引用。

* 运行时拿到的清单是**冻结的**：解析一次，之后数据内容变化不影响本次运行。
* 清单缺失/摘要不匹配 → 报错，不静默回退到 latest。

---

## 3. 运行生命周期

状态机（区分"计算完成"与"实验正式完成"）：

```
created ──► running ──► computed(pending-registration) ──► registered(verified)
                 │                    │
                 └──── failed         └──── (登记失败，非数值失败)
```

| 状态           | 含义                          |
| ------------ | --------------------------- |
| `created`    | 已分配 run id、冻结清单、确切配置版本，尚未执行 |
| `running`    | 执行中                         |
| `computed`   | 计算完成、产物已落盘，**待登记**          |
| `registered` | 已登记并验证完成                    |
| `failed`     | 数值执行失败（非登记失败）               |

关键：**`computed` ≠ `registered`**。产物先落盘，登记是其后、可独立重试的动作。

---

## 4. 产物登记

### 4.1 完整性

登记前对产物做完整性检查（哈希/存在性）。未通过 → 报错，不登记。

### 4.2 幂等与冲突检测（三规则）

| 情形           | 行为               |
| ------------ | ---------------- |
| 同一登记键 + 同一内容 | 返回已有记录           |
| 同一登记键 + 不同内容 | **报冲突**          |
| 不同运行 + 相同内容  | 允许共享产物，但分别保留运行关系 |

### 4.3 存储

产物存文件；目录只记录位置 + 内容摘要（sha256）。

---

## 5. 依赖关系

关系类型（显式标注）：**消费** / **生成** / **派生** / **复用**。

`findDependentRuns` 只返回"哪些运行存在依赖关系"，**不自动断言其科学结论失效**。
某数据版本被标记有问题 → 受影响结果标记**待复核**，历史记录保留。

---

## 6. 指标与信息契约

汇总指标至少明确六要素：

```
名称、定义版本、数值、单位、统计范围、聚合方式
```

"收益率 / regret / 效率"等指标**必须有参照对象与归一化定义**，否则数值可查但不可比。
信息契约（已知规则/隐藏参数/外生/累积状态）以**引用确定版本或摘要**的方式纳入，不每份记录手抄。

> DuckDB 选型可后置；**这些语义不可后置**。

---

## 7. 恢复与复现证据

* **补登记**：不依赖"失败后写待办"（可能在写待办前崩溃）。**已落盘的完成清单本身可被扫描、校验、重新登记**。
* **产物缺失检测**：登记时校验产物；历史产物缺失 → 标记，不静默忽略。
* **复现证据**：区分版本恢复（装了旧版）/ 行为恢复（旧版确定性测试通过）/ 数值恢复（预定容差内一致）/ 科学复现（独立重复成立）。

---

## 8. 接口清单（7 个，语义级）

| 接口                            | 输入           | 输出                 | 语义要点                          |
| ----------------------------- | ------------ | ------------------ | ----------------------------- |
| `registerArtifact`            | 产物位置+摘要+类型   | artifact id        | 幂等；同键同内容返回已有，同键不同内容报冲突        |
| `resolveDatasetVersion`       | 数据集 id+版本/别名 | 冻结清单(id+版本+sha256) | 解析一次冻结；缺失/不匹配报错               |
| `createRun`                   | 规格引用+配置+种子   | run id（状态 created） | 可事前登记；离线执行前先本地持久化 run id+冻结清单 |
| `completeRun`                 | run id+产物清单  | 状态 registered      | 产物先落盘再登记；失败不重算、不使结果作废         |
| `findDependentRuns`           | 产物/数据 id     | 依赖运行列表             | 只返回依赖关系，不自动断言失效               |
| `getRunStatus`                | run id       | 状态                 | 读/核对运行状态                      |
| `reconcileCompletedManifests` | 完成清单目录       | 补登记结果              | 扫描已落盘清单，幂等补登记                 |

---

## 9. 验收场景（6 个，实现后逐条验证）

1. **数据库暂不可用**：数值任务照常完成、产物落盘；登记失败不重算；DB 恢复后可补登记。
2. **重复登记**：同一 run 重复 completeRun → 返回已有记录，不产生重复。
3. **冲突登记**：同键不同内容 → 报冲突，不覆盖。
4. **写完产物后进程崩溃**：无"待办"记录也能从落盘清单扫描补登记。
5. **缓存命中**：记录为"复用已有产物"，不算新的独立数值重复。
6. **旧版本重新执行**：旧版算法读其兼容的冻结清单；数据库迁移单独版本化，不连带回退库结构。

---

## 10. 非目标（v0.1 不做）

* 不建 DDL / 表结构（后续经最小闭环验证后收敛）。
* 不引入 DuckDB（结果分析后置）。
* 不开发通用数据库抽象层（Drizzle 已封装访问边界，不追求"换连接串即迁移"）。
