执行摘要
截至 2026 年 9 月 10 日，我的判断可以压缩为一句话：

[ \boxed{ \text{范畴论优先的实验编排已经具备成熟的数学部件，但尚不存在成熟的端到端工程产品。} } ]

这里需要把“成熟”拆开看。对称幺半范畴、string diagram、hypergraph category、structured cospan、DPO 图重写、functorial data migration 等形式理论已经相当成熟；Catlab、AlgebraicRewriting、DisCoPy、open-hypergraphs 等已经证明这些理论能够落实为真实的数据结构、组合算法和重写程序。尤其是 structured cospan 给出了“带输入输出边界的开放系统”模型，DPO/hypergraph rewriting 给出了组合图的局部重写理论，而 Wilson 与 Zanasi 已进一步给出基于结构化 cospan/ACSet 表示的 string diagram 组合、tensor、term construction 和 functor evaluation 的线性顺序算法与对数级并行算法。

但是，“科学实验究竟应该被建模成哪种 category，什么是 object，什么是 morphism，什么可以复制，什么必须线性消费，随机性、外部设备、副作用、统计证据、hypothesis relation 如何进入语义”目前没有行业标准答案。 Catlab 自身仍明确定位为 applied/computational category theory 编程库，而非 workflow 系统或 proof assistant；AlgebraicRewriting 明确警告 API/行为尚未稳定；open-hypergraphs 仍有实验 API。换言之，数学地基成熟，不代表“科研语义 ontology + compiler + executor + provenance + agent”这一整栋楼已经有人造好。

生产工程世界则恰好相反：Nextflow、Dagster、CWL 等对 DAG、任务执行、HPC/cloud、缓存、恢复、资产 lineage 和 portability 已经有成熟经验。Nextflow 当前稳定版仓库显示到 26.04.6，并支持 pipeline caching、execution history、resume 等；其内置 data lineage 从 25.04 起仍标为 experimental。Dagster 已经是资产中心的生产 orchestration 系统，官方定位包含 lineage、observability、testing 和 production lifecycle；2026 年 7 月仍在持续发布 1.13.x。CWL v1.2.1 则已经形成供应商中立的正式工作流规范，但它明确把 workflow 定义为由依赖关系构成的 directed graph，而不是 categorical rewrite calculus。

AI4Science 又提供了第三条线。AI Scientist-v2 已经能够通过 progressive agentic tree search 自动提出假设、运行实验、分析和撰写论文，但其官方仓库明确警告它会直接执行 LLM 生成代码，因此必须在受控 sandbox 中运行。2026 年提出的 Experiment-as-Code Labs 更接近本文方向：实验是 declarative configuration，系统层负责 program analysis、安全检查、资源分配和 orchestration，再编译到设备 API；但其论文没有进一步建立 typed open-hypergraph、categorical composition 和 algebraic rewrite 语义。

理论基础与真正尚未解决的问题
范畴论优先的核心价值，并不是把普通 DAG 换一个数学名字，而是改变系统的基本语义单位。

传统实验对象模型倾向于：

text
Copy
Experiment
 ├── config
 ├── dataset
 ├── executor
 ├── metrics
 ├── lineage
 └── run()
最终非常容易回到你此前担心的 OOE——Object-Oriented Experimentation。继承、mixins、plugins 和状态生命周期不断扩展后，“Experiment”成为 God Object。

关系优先则把实验片段看成：

[ f:X\rightarrow Y ]

而复杂实验是：

[ X\xrightarrow{f}Y\xrightarrow{g}Z \qquad\Rightarrow\qquad g\circ f:X\rightarrow Z. ]

多个彼此独立的变换通过 tensor 组合：

[ f\otimes g: X\otimes A\rightarrow Y\otimes B. ]

这正对应 symmetric monoidal category 和 string diagram 的基本组合结构。Structured cospan 又进一步提供“开放系统具有显式输入、输出 boundary”的数学形式：

[ L(a)\rightarrow x\leftarrow L(b), ]

在适当条件下，这些开放系统构成 symmetric monoidal / hypergraph category。它因此非常适合表达“实验片段不是封闭对象，而是拥有可组合 boundary 的过程”。

进一步，如果科研探索被解释成：

[ G\Rightarrow G' ]

那么实验“扩展”不再等价于复制目录或创建 Experiment subclass，而是修改 research term 的局部结构。String Diagram Rewrite Theory 给出了以 DPO hypergraph rewriting 对 Frobenius/string-diagram rewriting 建模的 sound/complete combinatorial interpretation；AlgebraicRewriting 已经工程化实现 DPO、SPO、SqPO，并能在 C-Sets 等数据结构上进行规则匹配和重写。

但这里有几个非常容易被“范畴论很优雅”掩盖掉的工程问题。

首先，普通 SMC 是线性的，科研数据流却经常 fan-out。 在普通 monoidal syntax 中，一条 wire 不能凭空被复制；hypergraph/Frobenius structure 可以提供 spider，从而表达复制、合并等 wiring。DisCoPy 的 Hypergraph API 就明确提供 spiders，而 string-diagram rewriting 的 Frobenius 结构也正是围绕这种 wiring 建模。

然而，对于科研系统，不能直接声明“所有东西都有 spider”。例如：

text
Copy
immutable dataset reference -> 可以复制引用
physical sample            -> 不可以复制
GPU allocation             -> 不可以复制
chemical reagent aliquot   -> 只能按资源规则拆分
model artifact             -> 可以共享
secret capability          -> 不应该随意复制
因此推荐在 type 中增加结构模态：

ts
Copy
type StructuralMode =
  | "shareable"      // 可 fan-out
  | "affine"         // 可丢弃，不可复制
  | "linear";        // 必须且只能消费一次
这不是一个装饰性的 schema 字段，而是 categorical composition checker 的一部分。

其次，数学 tensor 不能简单等价于“并行执行”。

[ f\otimes g ]

在语义上表示两个 component 的 monoidal juxtaposition；它们能否真的同时在两块 GPU 上运行，还取决于资源、side effect、锁、外部服务和 scheduler。因此：

[ \text{semantic independence} \neq \text{physical schedulability}. ]

executor interpretation 可以利用 tensor 暴露出的 independence，但不能由 syntax 直接保证并行。

第三，随机实验不是纯函数。 ML 训练、Monte Carlo、外部 API、仪器读数都可能使：

[ f:X\to Y ]

不再具有普通 deterministic function 的运行语义。DisCoPy 已包含 Markov-category 相关结构，说明 categorical toolkit 本身可以继续向概率过程扩展，但 MVP 不应试图一次解决完整 stochastic semantics。

我建议第一版只冻结：

ts
Copy
determinism:
  | { kind: "strict" }
  | { kind: "seeded"; seedParam: "seed" }
  | { kind: "external" };

effects: readonly EffectCapability[];
随后让 cache、reproducibility 和 agent policy 根据这些声明工作。

第四，所谓 semantics → executor functor 必须成为可检验的工程承诺，而不只是漂亮术语。

理想情况是：

[ F_{\rm exec}(\mathrm{id}_X)
\mathrm{id}_{F(X)} ]

[ F_{\rm exec}(g\circ f) \simeq F_{\rm exec}(g)\circ F_{\rm exec}(f) ]

[ F_{\rm exec}(f\otimes g) \simeq F_{\rm exec}(f)\otimes F_{\rm exec}(g). ]

但是生产编译器可能插入 artifact staging、serialization、sandbox boundary、resource acquisition，因此严格 equality 往往不成立。更现实的目标是 strong/lax monoidal interpretation 或 observational equivalence。

所以第一版文档里我甚至不会正式宣称：

“Temporal compiler is a functor.”

我会写成：

law-tested lowering interpreter

等 identity/composition/tensor preservation 的测试和语义等价关系真正定义清楚以后，再升级数学承诺。

这一点是区别“范畴论驱动工程”和“给 DAG 贴范畴论标签”的关键。

现有实现与生产工具的比较
现状其实呈现出很清晰的“两头成熟、中间断裂”。

一头是 categorical computation。Catlab 是目前最系统的 applied/computational category theory 工程框架之一，能够表示 categorical doctrines、typed symbolic manipulation、wiring diagrams，并提供 JSON/GraphML serialization；但其官方文档明确说它不是 theorem prover、proof assistant 或用户级 GUI。

AlgebraicRewriting 在 Catlab/C-Set 基础上直接实现了 DPO、SPO、SqPO、PBPO 等图重写，以及 application condition、attribute variable、graph process 等能力，不过官方仓库明确注明仍处于活跃开发、API/behavior 不应假定稳定。

open-hypergraphs 直接实现 Wilson–Zanasi 的 string-diagram 数据结构思想，当前 Rust 库提供 construction、composition、data-parallel algebraic operation、layering、functor 等能力；仓库示例依赖 0.2.10，而且仍有单独的 experimental feature，因此更适合作为 IR/algorithm 参考，而不是拿来承担生产科研 orchestration。

另一头是生产 workflow。Nextflow 在科学/HPC pipeline 上已经提供相当完整的缓存、resume、执行历史、远端运行等工程能力，CWL 则形成了 vendor-neutral 的 portable workflow specification；Dagster 在数据资产 orchestration、lineage、observability 和生产生命周期方面成熟度更高。

因此不能简单问“Catlab 和 Nextflow 哪个更好”，它们解决的是不同层。

Agentic science 与我们的缺口
AI Scientist-v2 的研究搜索空间主要是 agentic tree search over experiments/code：

[ s_0 \rightarrow {s_1,s_2,\ldots} \rightarrow \text{evaluate} \rightarrow \text{continue} ]

而不是：

[ G \xRightarrow[\text{typed rule }r]{} G' ]

其论文明确说明 progressive agentic tree search，由 experiment manager 管理；官方仓库也直接警告系统执行 LLM-written code 可能带来危险 package、非受控网络和额外进程风险。

Coscientist 则证明另一侧已经成立：LLM 可以把规划、文档检索、Python 执行和实验设备 API 组合起来，完成化学实验设计与执行；但它的基本 action space 仍是 planner/tool/API，而不是一个有组合公理的 experiment IR。

2026 年的 Experiment-as-Code Labs 是目前我认为最靠近这条架构思想的公开研究之一：

论文明确提出这套分层，但还没有把 declarative configuration 建模为 typed open hypergraph，也没有以 categorical rewrite 作为 autonomous exploration 的受控 action space。

所以真正可能形成研究贡献的部分不是：

“我们也做一个 AI scientist。”

而是：

[ \boxed{ \text{把 Agent 的 action space 从 arbitrary code mutation} \rightarrow \text{typed semantic rewrite} } ]

这是现有 autonomous science 和 formal/compositional systems 之间非常明显的一条缝。

Compilation	LoweringVersion, ExecIR, Plan	是

然后 provenance 通过映射导出，而不是成为 semantic graph 的内部运行状态。

RO-Crate 1.2 则已经是 Recommendation，以 JSON-LD 打包 research data、metadata，并允许描述 workflow/scripts 和 provenance，很适合作为“一键归档科研对象”的外部格式。

如果未来需要把运行事件接入数据平台，还可以可选输出 OpenLineage。其核心模型正是 run/job/dataset/event，而不是 research semantics，因此它更适合作为 operational lineage adapter，而非主科研模型。

最小可行语义内核与 TypeScript 设计
我会刻意把 MVP 限制在自由生成的、typed symmetric monoidal/open-hypergraph 语法，而不是一开始就做“所有 applied category theory”。

核心 signature：

[ \Sigma=(O,G) ]

其中 (O) 是 wire/object types，(G) 是 typed generators：

[ g:A_1\otimes\cdots\otimes A_m \rightarrow B_1\otimes\cdots\otimes B_n. ]

复杂实验只能通过少量构造得到：

[ {\mathrm{id},\circ,\otimes,\mathrm{swap},\mathrm{copy?},\mathrm{discard?}}. ]

Wilson–Zanasi 已证明 open/string diagram 的 composition、tensor、functor application 可以建立高效的数据结构算法，因此采用 open hypergraph 并不天然意味着运行时一定不可扩展。

Rewrite 不应首先允许 arbitrary code
第一类 rule 应非常保守：相同 boundary 的 generator replacement。

例如：

[ \mathrm{evaluate}_1: Model\otimes Test\rightarrow Metrics ]

替换成：

[ \mathrm{robustEvaluate}_2: Model\otimes Test\rightarrow Metrics. ]

可以写：

ts
Copy
const robustEvaluation = rewriteRule({
  id: "robust-evaluator/v1",

  match: edge({
    generator: "evaluate@1",
    input: [Model, TestSet],
    output: [Metrics],
  }),

  replace: edge({
    generator: "robust-evaluate@2",
    input: [Model, TestSet],
    output: [Metrics],
  }),

  require: [
    sameBoundary(),
    registeredGenerator(),
    effectSubsumption(),
  ],
});
对应形式上：

[ L\xleftarrow{}K\xrightarrow{}R ]

其中 (K) 保留 interface，而 (L,R) 是替换前后的局部开放系统。DPO rewriting 以及 structured-cospan rewriting 已经为这种“保留 interface 的局部变化”提供理论基础。

工程挑战、安全、性能与验证方案
最大的工程风险并不是“实现 (\circ) 很难”。Composition 很容易。

真正难的是确定哪些 categorical laws 对科研世界成立。

语义与执行事实必须严格分开
例如：

text
Copy
“这个实验结构是什么？”
应该由 SemanticIR 回答。

而：

text
Copy
“2026-09-10 13:22 的第三次运行失败了吗？”
应该由 execution event store 回答。

如果把运行状态直接写回 categorical graph：

text
Copy
edge.status = "failed"
就会立即重新进入 mutable object graph。

所以：

[ \boxed{ \text{Semantic graph immutable} } ]

而：

[ \boxed{ \text{execution history append-only facts} } ]

这和你现有 Plan identity 避免时间戳、execution ID 的方向高度一致。

Semantic identity 与 byte identity 不能混为一谈
范畴论通常关心“up to isomorphism”；AlgebraicRewriting 的官方 demo 也特别指出 C-Sets 通常被视为 up to isomorphism，极限/余极限过程可能改变顶点/边的具体排列。

而 AdaPDC 当前非常需要：

text
Copy
stable deterministic bytes
stable digest
stable node identity
这两件事并不冲突，但需要明确区分：

[ \text{storage identity} \neq \text{semantic equivalence}. ]

MVP 不建议尝试“任意同构图都自动得到完全相同 SHA-256”。

更现实的是：

text
Copy
Storage equality:
canonical serialization bytes 相同

Construction equality:
normalization 后 AST/IR 相同

Categorical equality:
通过 laws / isomorphism / rewrite theory 判等
后者逐步增强。

否则第一阶段就会掉进 canonical graph isomorphism、normal-form 完备性之类并不直接产生科研价值的大坑。

Rewrite matching 必须受限
AlgebraicRewriting 能进行一般 C-Set homomorphism search，并支持 application conditions，这说明通用 matching 能力是可实现的；同时也提醒我们生产系统里不能让 Agent 提交任意巨大 pattern，然后期望所有图都可以低成本搜索。

第一阶段规则应限制为：

text
Copy
bounded local pattern
typed exact generator constraints
有限 attribute predicates
禁止 arbitrary recursive graph query
明确 match cardinality
并为：

text
Copy
generator type
boundary signature
research relation
parameter key
effect class
建立 index。

可重复性应分等级
不要承诺“所有 scientific experiment 都 bitwise reproducible”。

[ \boxed{ \text{真实科研演化能否主要表现为少量稳定 generator 上的局部 typed rewrites？} } ]

如果做完：

以后发现绝大部分真实研究仍必须：

那么 category-first 应退回较薄的 workflow/typing layer，而不应该继续扩张。

反之，如果实验变化可以从：

text
Copy

change config
repair dependencies
rerun everything
压缩成：

[ G\xRightarrow{r}G' ]

并且旧的 artifacts、subgraphs、evidence 都能被局部复用，那么这套架构的价值会远远超出“更好看的 DSL”。
