**v2 的目标是：在统一任务、执行模型、预算和最终判据下，比较 MasRouter、EvoRoute，以及接入千问决策模型后的方案，确定收益来自哪里、是否覆盖额外开销。**

这是待执行的实验协议。下文的样本量、预算档位和验收门槛都是建议值；在开发阶段确定后冻结，不按测试结果修改。

**1．研究问题与实验边界**

两篇论文提供不同的干预位置：

- **MasRouter，arXiv:2502.11133**：联合考虑协作方式、角色分配和执行模型选择。genui{"citation":{"ref":"turn20view0"}}
- **EvoRoute，arXiv:2601.02695**：利用历史经验，在执行过程中逐步选择模型，兼顾性能、成本与时间。genui{"citation":{"ref":"turn20view1"}}
- **千问决策模型**：提供结构化选择接口，可替换路由中的选择环节；其 agent 路由效果需要本实验验证。genui{"citation":{"ref":"turn20view3"}}

v2 回答四个问题：

| 问题 | 对应实验 |
|---|---|
| 根据当前状态动态选模，是否优于固定配置？ | 固定配置与 EvoRoute 比较 |
| 协作结构、角色配置的变化，是否有额外价值？ | MasRouter 完整版与固定结构消融比较 |
| 专门决策模型是否改善选模？ | EvoRoute 原选择器、通用模型、决策模型比较 |
| 收益是否超过训练、经验积累和在线决策的成本？ | 部署成本与构建成本分别核算 |

**完整 MasRouter 与完整 EvoRoute 的比较属于系统比较，不能直接解释为“任务级与逐步路由”的纯粹差异。** 两者还改变了学习方法、可用信息和协作结构。

**2．数据集与划分**

以代码任务起步，便于使用独立、可执行的最终判据。

| 层次 | 数据与规模 | 用途 |
|---|---|---|
| 接线测试 | HumanEval+/MBPP+ 中约 40 题 | 检查模型接口、工具、预算与评测链 |
| 主实验 | DS-1000 | 比较路由策略与决策模型 |
| 迁移实验 | SWE-bench Verified 的预先抽样子集 | 检查结论能否迁移到仓库级修改 |

DS-1000 建议自行划分为约 **200 题训练、100 题开发、700 题测试**，按库分层，并将近重复题归入同一划分。实际数量可因分组略有变化。

这是**本实验的自定义划分与多步 agent 协议**，不等同于官方排行榜设置。DS-1000 的 `code_context` 包含测试与参考解，必须放在独立评测端；agent 只得到题目和允许公开的执行环境。genui{"citation":{"ref":"turn20view2"}}

具体约束：

- 训练集：训练 MasRouter、构造 EvoRoute 经验库。
- 开发集：选择固定配置、提示、预算、回退规则与超参数。
- 测试集：仅在全部冻结后运行；测试结果不回流经验库。
- agent 可以运行题面示例、自写测试；不能访问最终隐藏测试。
- 所有方法面对同样的可见信息。

预算有限时，可事先从测试部分抽取 200 题。但这更可能得到“精度不足”，不能保证识别 3 个百分点的差异。

**3．统一执行环境**

采用三个固定执行模型 \(M_1,M_2,M_3\)，覆盖不同成本与能力特征。具体型号在接线阶段确定，记录完整模型标识、供应商和日期。

所有方法共用：

- 工具集合、权限与沙盒；
- 角色提示模板和上下文压缩规则；
- 公开测试与最终评测程序；
- 单任务金额、墙钟时间和最大步数限制；
- API 失败处理与产物提交规则。

固定协作结构建议为：

\[
\text{Planner}\rightarrow\text{Coder}\rightarrow\text{Reviewer}
\rightarrow\text{Coder 修订}
\]

在预先规定的条件与预算内重复审查—修订。所有固定结构组使用相同条件。

每个角色可以包含多次模型调用。“逐步选模”明确指：**每次执行模型调用之前选择模型**。

先使用一个共同运行器完成主实验，再把领先方案移植到 kimi-code 或 qwen-code；不要在第一阶段同时改变宿主和路由算法。

---

**4．实验组：共同基线、两个比较模块**

| 编号 | 方法 | 协作结构 | 模型选择 |
|---|---|---|---|
| B0 | 单模型基线 | 固定 | 开发集选定的一个模型 |
| B1 | 固定异构配置 | 固定 | 开发集选定的角色—模型映射 |
| B2 | 同模型多次尝试 | 固定尝试协议 | 同一模型，多次候选后选择 |
| M0 | MasRouter 固定结构消融 | 固定 | 保留适配后的模型分配机制 |
| M1 | MasRouter 完整版 | 可变 | 协作方式、角色、模型联合选择 |
| E0 | EvoRoute | 固定 | 原逐步选模机制 |
| E1 | EvoRoute + 通用对话决策 | 固定 | 通用模型选择下一执行模型 |
| E2 | EvoRoute + 千问决策模型 | 固定 | `decision-model-preview` 选择 |

B2 的候选只能根据公开测试或冻结的选择器筛选。不能用隐藏测试挑出最佳候选，再报告该结果。

E0/E1/E2 共用经验库、检索、候选过滤与状态构造。E1/E2 得到语义相同的输入；区别是决策服务及其接口。

**先不加入混合全部机制的 Hybrid。** 八组已经足够回答主要问题；混合方案需要在知道各组件贡献后再设计。

若源码不可取得或原设置无法复现，应明确标为“依据论文重实现”或“方法迁移”，不能声称复现了论文原始成绩。

**5．千问决策模型如何接入**

运行器在每次执行调用前构造状态：

```text
任务与本步目标
当前角色、当前产物
最近工具结果、公开测试反馈
剩余金额、时间和步数
候选模型的价格与历史表现
检索到的训练经验、样本数与不确定性
```

E2 使用 `choice` 返回候选模型标识。预算约束、合法选项检查、超时与回退由程序执行。

第一阶段只开放**选模权限**，不同时开放最终验收、修改测试或提前宣布成功的权限。

固定以下规则：

- 非法输出或调用失败：按预注册规则退回 E0。
- 重试次数与超时固定。
- 回退前已经产生的费用、延迟全部计入 E2。
- 没有历史证据的模型明确标为未知，不能伪造成功率。
- 状态构造若调用额外模型，计入其成本。

`probabilities` 是选项分布，不能直接当作各执行模型的任务成功率；`confidence` 也需要经验验证后才可用于接管阈值。

**6．先验证评测链，再比较算法**

第一项实际测量是对最终评测适配器做挑战测试。

从训练或开发题中选取约 30 题，每题准备：

1. 已知正确、可独立核验的产物；
2. 未实现要求的空白或未完成产物；
3. 看似合理但有明确语义错误的产物；
4. 只匹配题面示例、不能泛化的产物。

运行与主实验相同的最终评测路径，检查：

- 正确产物是否因环境、路径或封装错误被拒绝；
- 明确错误是否被接受；
- 超时、异常、空输出是否误计为通过；
- 重复评测结果是否稳定；
- 提交产物是否确实是被评测的那一个。

**任何已确认的适配器错误必须先修正。** 这批测试通过只证明检查过的路径正常，不证明验证器完美；报告挑战样本数与错误率，不写“已验证绝对可靠”。

**7．训练、调参与执行步骤**

| 阶段 | 具体操作 | 产出及进入下一阶段的条件 |
|---|---|---|
| A．冻结接口 | 定义状态、动作、日志、预算与评测接口 | 所有方法可接入同一运行器 |
| B．评测链挑战 | 执行上述正确/错误产物测试 | 已知适配器缺陷清零，保留剩余局限 |
| C．接线试跑 | 约 40 题，检查完整轨迹 | 无隐藏信息泄漏；调用与计量可追踪 |
| D．训练与经验收集 | 仅使用训练集 | MasRouter 参数与 EvoRoute 初始经验库 |
| E．开发比较 | 100 题开发集上调参与比较 | 冻结全部配置、主预算、样本量和主要比较 |
| F．正式测试 | 所有冻结方案跑独立测试集 | 一次性统计预注册指标 |
| G．消融与迁移 | 针对剩余问题追加实验 | 明确标为后续探索或独立确认 |

训练公平性分两层：

- 共用训练题与可访问的信息；
- 为每种方法设置相同的最大数据收集预算、调参预算，并记录实际消耗。

不要求不同方法执行完全相同的训练流程；方法本身的样本效率就是比较对象。若某方法在预算内未训练充分，也要如实报告。

主实验冻结经验库。持续在线更新另设实验，避免测试顺序成为隐含训练过程。

**8．预算、计量与停止规则**

在开发集上确定单任务主预算：

\[
B=(C_{\max},T_{\max},K_{\max}),
\]

分别表示金额、墙钟时间与模型调用次数上限。所有组共用相同上限，不要求花完预算。

低、中、高预算可做探索，但正式主比较只选一个预注册档位，避免同时扩张样本规模。

计量至少分开：

\[
C_{\mathrm{运行}}
=C_{\mathrm{执行模型}}
+C_{\mathrm{决策}}
+C_{\mathrm{检索与摘要}}
+C_{\mathrm{其他运行资源}}.
\]

另记训练、经验构建和调参成本 \(C_{\mathrm{构建}}\)，报告：

\[
C_{\mathrm{累计}}(N)
=C_{\mathrm{构建}}+N\bar C_{\mathrm{运行}}.
\]

保存原始 token、缓存命中、供应商计量、实际账单及计价版本。**不同模型的 token 不直接当作等价成本单位；无法可靠换算的套餐 credits 单列，不强行折美元。**

停止规则统一：

- 主动提交；
- 达到金额、时间或步数上限；
- 遇到预定义的不可恢复错误。

超时后评测截止前最后一个完整产物；没有有效产物则失败。预算内成功与否是可观察结果；如果额外分析“最终要多久才能成功”，未成功轨迹属于删失数据，不能记为恰好在超时时成功。

**9．主要假设与验收**

v2 建议只预注册两项主要比较：

| 假设 | 比较 | 能得出的结论 |
|---|---|---|
| H1：动态路由具有部署价值 | E0 对 B1 | 该动态系统是否优于固定异构配置 |
| H2：专门决策模型具有增量价值 | E2 对 E0 | 替换选择环节是否值得 |

其余为次要比较：

- M1 对 M0：改变协作结构与角色配置的贡献；
- E2 对 E1：专门决策服务与通用模型决策的差异；
- 候选方案对 B0/B2：是否优于同模型及同模型多试；
- M1 对 E0：完整方法的部署表现。

对 H1/H2，建议保留前述工程验收条件：

\[
\begin{aligned}
\operatorname{LCB}(\Delta p)&>-0.03,\\
\operatorname{UCB}(\bar C_A/\bar C_B)&<0.90,\\
\operatorname{UCB}(\bar T_A/\bar T_B)&<1.10.
\end{aligned}
\]

即：通过率下降不超过 3 个百分点，平均运行成本至少下降 10%，平均时间增加不超过 10%，且置信区间支持这些判断。

**这是一种部署偏好，不是唯一科学成功标准。** 若通过率显著提高但成本也提高，应报告新的性能—成本取舍，不能简单归为“算法失败”。同时给出完整三指标结果与 Pareto 图。

三种判定：

- 全部达到预注册门槛：支持部署价值。
- 明确跨向不可接受一侧：不满足该部署目标。
- 区间跨门槛：精度不足，未决。

**10．统计、样本量与运行规模**

每题建议运行三次，用于估计随机性；但独立统计单位仍是**任务**。按任务聚类、按库分层计算配对置信区间，不把三次运行当三道题。

开发结束后，根据观察到的配对差异与方差做功效模拟，冻结测试样本量。700 题也不保证足以确认 3 个百分点的非劣界限。

主要比较采用预注册的多重比较控制，例如 Holm 校正或同时置信区间。不得因为某一组结果较好，临时提升其为主要假设。

规模上：

- 八组 × 200 测试题 × 三次 = **4,800 条完整轨迹**；
- 八组 × 700 测试题 × 三次 = **16,800 条完整轨迹**。

因此，预算有限时建议采用两层安排：

1. 开发集上比较全部八组；
2. 正式确认优先保留 B1、E0、E2；若要正式声称优于通用决策，再保留 E1；
3. MasRouter 模块使用同一预封存测试集独立安排预算，未完成前不下胜负结论。

测试必须按题目分块、组间随机交错运行，减少供应商负载变化的影响。

**11．主实验之后才做的消融**

| 消融 | 检验的疑问 |
|---|---|
| 根据开发集模型使用比例随机选模 | 收益是否只来自多用了强模型，而非状态匹配 |
| EvoRoute 每个角色只选一次模型 | 逐步调整是否有额外价值 |
| E2 去掉检索经验 | 决策模型依赖真实经验，还是仅凭模型描述 |
| E2 低置信度退回 E0 | 置信度是否能支持选择性接管 |
| MasRouter 结构 + EvoRoute 逐步选模 | 两种机制能否互补 |
| 在第二个 harness 中复跑 | 效果是否依赖宿主实现 |

置信度阈值只能在开发集选择；测试时报告接管覆盖率、任务收益和总成本。高置信度不自动代表选择正确。

**12．每次运行必须留下的记录**

每条轨迹至少保存：

```text
任务 ID、划分与数据版本
方法配置、代码提交、模型完整标识
决策前状态哈希、候选集合、检索经验版本
所选模型、返回分布与置信度
全部模型和工具调用、重试、回退
原始 token / credits / 费用及计价版本
客户端起止时间、停止原因
最终产物哈希、独立评测结果与评测器版本
```

第一批可交付成果应是：**统一运行器、通过挑战测试的评测适配器、冻结的数据划分，以及八组方法在开发集上的成本和错误画像。** 随后再启动正式测试；这样最终获得的是可以解释和复核的比较结果。
