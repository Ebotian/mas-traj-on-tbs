# canary 假设验证(已有资产)· 2026-10-12

**验证对象**(用户 2026-10-12 定):给单个 agent 并联一个助手 **canary**(暂名),随其运行、每步滚动做
"向前多步、正负成对"的**本地**预测以辅助决策;canary 的访问面与其绑定 agent **唯一绑定且一致**。
本次只做"已有资产"的假设验证,不新建任何东西。

**资产与口径**:`jobs/agent` 全族 20 个收集跑(17 NORMAL + w7/m1/m2 三例 ABNORMAL)与 40 条单侧轨迹,
全部时间戳/内容取自采集包(x/、chats、gate.log、Dockerfile);只读。
复跑:`python3 canary_verify.py`;机器可读:`cases.json`(均在本目录)。

## 判定(三句)

1. **"正负成对"作为判据:成立且必要。** 三个异常案都能在"绑定 agent 自己的访问面"内找到正/负对立证据。
   而把负信号(对侧转写静默)单独当检测器:在 17 个 NORMAL 里 4 跑有 ≥360s 单侧间隔
   (tumor-1 一侧 8 段、tumor-2 一侧 4 段、bump-0251 a 435s、w6n1 b 600s)、3 跑 ≥600s——必误报;
   三异常中它又漏掉 m1(单侧最大仅 205s)、到 m2 恰好与事故同刻才越过。配对(存活/职责/会合)后:3/3 覆盖,
   所提规则在本语料上不触发任何 NORMAL 案例。
2. **"向前多步"的可机械验证核 = 职责/会合账本。** m1 的"END 前 m2-done/ckpt-m2 缺失 ⇒ 预测 ABNORMAL"
   与 m2 的"会合命名错位"(a 等 `pos-b-r7`,而 b 从未写它、只写了 `pos-b-r8`)都是本地、向前、可机械计算的状态投影,
   不需要学习器。
3. **学习型逐步预测器:n=3 异常,不可检验,不宣称。** 第一阶段应上机械配对规则;学习头是二期
   (训练目标即上述配对状态)。

## 仪表发现(本次验证的额外硬产物;canary 一期应先修这些)

1. **task-microarch 镜像缺 inotify-tools**:现行 `harbor-runs/build/task-microarch/environment/Dockerfile`
   只装 `bash git curl ca-certificates`(tumor 的 task-restricted 镜像在 2026-10-10 即装了 inotify-tools,
   注释写明"backs the gate's event-driven peer wait")。wait_* 脚本里 `inotifywait … || true` 把
   "command not found" 吞掉 → **毫秒级自旋**;"静默"计数器按循环返回次数计数、消息按"计数×300 s"记账。
   实测:m2 的 wait 退出 = a 静默 360 s 整 + 5ms(collapse ≈3.3×),消息 "~900 s" 为假(真实 360s)。
   m1 的 dead-exit 0.0s 与自旋一致;w7(有 inotifywait)实测整窗 300.1s 判死,与脚本注释
   "A dead peer exits 2 at once" 亦不符(实为窗粒度)。
2. **同镜像缺 procps**:b 的手动存活探测 `ps -p 77` 秒回 "PID-A NOT RUNNING"
   (来自 `||` 兜底),而 kill -0 全程证明 pid 77 活着——唯一有意义的存活通道被 b 自己的检查否定,把它推向 abort。
3. **语料级**:258 次 wait_* 调用中,"silent for ~" 全语料只真实响 **1 次 = m2 的误杀**;
   "peer … dead" 真实响 2 次(m1 0.0s、w7 300.1s)全对;9 次 590/600s 是 qwen 工具级超时,与脚本无关。

## 访问绑定(1:1)结论

canary 所需每个信号,在绑定 agent 的既有工具面里都有同源用法:peer 转写 mtime ← wait 脚本的 peer_state;
pid ← kill -0;x/ 文件 ← inotify/读;git、board、gate.log ← 各自工具;进程表 ← ps(w7 07:48:42 的
"comm-only ps、不读对侧 args"是既有纪律,可作 canary 的泄漏边界先例)。**全部可在不越封印、不新增权限的前提下取得。**

## 追问(2026-10-12 晚):分析信号的置信度与"低于 50%"的地板

- **口径修正**:17:3 不平衡下"准确率 50%"不是随机地板(零信号预测器就有 85%);无信息地板是
  均衡准确率/AUC=0.5。"低于 50%"的物理含义是**反信号**——已见一次真例:m2 的"静默 360s ⇒ 判死"
  (同一规则还会在 4 个 NORMAL 跑上触发)。行动阈值另论:成本不对称(误杀≈整跑)⇒ 远高于 50%;
  最近公开工作点 = s=f=0.95〔仓库 2026-10-12 钉版〕+ 89–97% 决策精度〔论文原话,arXiv 2609.02783 v1,
  见调研档;未本机复现,且为"敢停时"的条件精度〕。
- **可测性现状**:n=3 异常、无留出、无校准 ⇒ "置信度有多准"**现在没有可信数字,任何报数都是编的**;
  horizon 曲线要按调研档 §2.2/§3 的评估设计(按跑留出/校准/阈值扫描)在"数百次跑"量级上测。
  一期只上机械规则(确定性,无需校准)。
- **本次补测(重复类)**:
  - 严格同串重复(相邻):最长 3 连同时出现在异常(microarch-2 a)与正常(tumor-2 a)两侧;
    命令全域 ≥3 次重复:m1 a 3 条、w6n2 a(正常)2 条 ⇒ **无正分离**。
  - 摩擦代理(gate refs-block):异常 {w7:0, m1:3, m2:3} vs 正常最高 6(w6np)、多数 w6r* 为 5 ⇒
    异常位于正常分布之内/之下。m1 终局前的 refs 修复循环是**近重复**(逐字不同,严格计数测不到)——
    信号要有信息,需"近重复 + 期间什么变了"的上下文语义。
- **归纳**:对诚实校准的预测器,horizon 拉长只会回落到基线率(增量→0);**低于 50% 是方向性失效,
  不是 horizon 现象**,且以"确定性的错误"出现(比低置信更危险)。canary 的向前投影应压在状态分叉
  (职责/会合/存活的事实)上,而不连续预测整段未来。
